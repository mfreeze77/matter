## Implemented boundary and acceptance

The milestone adds immutable exact rule definitions, isolated self-contained
domain schemas, detached bounded input preparation, deterministic and recorded
bindings, typed attempt results, host-admitted certificate applicability,
direct prerequisite admission and currentness/control seams. It returns
uncommitted judgment and evaluation receipt inputs using existing core kinds.
There is no new core wire variant, SQLite migration or dependency.

| Acceptance | Executed evidence |
|---|---|
| AC-1: timeout cannot satisfy a negative prerequisite | A timed-out attempt has no semantic conclusion; prerequisite admission blocks it. Missing evidence, not-applicable, ambiguity and conflict remain distinct outcomes. Independent successful bundles survive another failure. |
| AC-2: deterministic and recorded bindings share a neutral input | Both validate one exact ordered packet carrying complete rule meaning, binding, proposition, subject, evidence and locators, omissions, coverage, context, knowledge cut, dependencies and control identity. Changed ordered input misses a recording. |
| AC-3: undefined labels and nonexistent evidence are refused | Fresh and consumed results share exact schema/label/status/citation/proposal validation. Invented IDs, altered locators and undeclared proposals cannot become usable judgments. |

Direct prerequisite mapping requires the host-selected original input material,
matching digest, scope, rule, binding and dependency manifest. A result for the
same rule but another undeclared input cannot substitute. Different propositions
are permitted only through the explicit host mapping. Future-produced results
cannot enter an earlier knowledge cut or admission, and the knowledge cut cannot
follow actual attempt time. Certificates and due/expiry checks use actual
evaluation/consumption time, not the historical evidence selection boundary.

Qualification remains independent of semantic output and host authority. An
allowlisted certificate must match the exact rule, binding, schemas, preparation,
task and threshold and be currently valid. Missing certificates remain unknown;
recorded responses cannot waive qualification. A qualified score never grants a
transition, write, dispatch or other host capability.

## Real host-control integration

`tests/integration/test_rule_controls.py` passed four checks using real scoped
SQLite and `ControlService`, with no evaluator runtime change:

1. A separate control handle cancels while the deterministic binding executes;
   the post gate removes the semantic conclusion.
2. An explicit test-only host handler persists the predecessor judgment and
   receipt. A correction to its original target makes it stale despite a new
   downstream target token with the same epoch integer. The exact original
   token resolver refuses admission and persisted history remains unchanged.
3. A current assessment denial refuses a qualified recording before invocation.
4. A permission-checked source view refuses new packet preparation after a read
   denial while retaining the immutable historical source record.

Original token contexts are never recaptured. Inside an existing snapshot the
host resolver checks its retained token digest and uses
`ControlService.require_current(view, ...)`; `check()` on that same SQLite
handle would attempt a nested snapshot and fail closed. The runner's separate
pre/post `check_control` callback operates outside that dependency snapshot.
These checks do not implement the later atomic assessment commit or durable
input/control-context restoration.

## Host obligations and limits

Host configuration is trusted: the host authenticates installed bindings,
schema and locator declarations, certificate admission, actor/authority policy,
source access, explicit prerequisite mapping and actual clocks. No schema or
descriptor authenticates untrusted content by itself. Raw storage remains a
privileged host interface. Currentness callbacks read fresh authorized snapshots;
later publication must still perform its atomic currentness/authority checks.

The local elapsed limit is cooperative and checked after a synchronous callback
returns. It is not preemptive cancellation, a memory limit or a Python process
sandbox. Failed or cancelled execution supplies no domain conclusion, and an
unavailable original artifact is not given an invented digest or replay claim.

No live provider, certificate issuance or accuracy certification, policy DAG,
general transitive invalidation service, durable evaluator persistence or replay,
assessment publication, scheduler, native transport, deployment, training,
production noise reduction or live attention usefulness was implemented or
qualified in this milestone.
