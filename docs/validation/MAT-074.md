# MAT-074 compatibility candidate

Status: implementation candidate, SDK `0.1.0.dev21`. Independent review and
installed-wheel closeout remain pending; no completed receiving deployment,
provider qualification or new SQL format is claimed.

## Scope and existing owners

The [compatibility policy](../../schemas/versioning.md) adds opt-in envelope
admission around existing payloads. Native readers, present controls, access,
policy fingerprints and qualification remain authoritative. Frozen monitoring
1.0/1.1 and assistant-review 1.0 are unchanged. The migration manifest exposes
the existing checksummed SQLite registry; the migration engine and physical
schema version 1 are unchanged.

The JavaScript client reuses the original MAT-002 encoder, extracted into a
shared conformance codec, and adds the missing strict parser. It is a
compatibility reader, not a second native Matter runtime or new host client.
All examples and databases are synthetic. StateCivics, crawler and DIAT
repositories, images and deployment are untouched.

## Actual candidate checks

- Full `tests/contract` selection: **197 passed in 8.016s**, including six new
  compatibility tests and **28** shared accepted/refused envelope cases.
- Existing migration/backup selections plus the new multi-record migration
  episode: **28 passed in 5.554s**.
- Independent JavaScript codec: **26 canonical positives**, **8 exact-source
  vectors**, **53 strict refusals** passed. Compatibility cases compare native
  accepted canonical bytes/digests and refusal codes with Python.
- Native SQLite create result: both readers preserve its outcome, identities,
  references and unknown envelope extensions; the original native command's
  exact retry returns its original result.
- Changed rule content under the same output shape and removed consumer-required
  semantic declarations both refuse. Recognition is not proof the payload used
  those semantics; native admission still checks actual context.
- The migration episode includes an actual claim supersession, a stored typed
  unresolved-proposal fixture and a native authorized-but-unknown delivery.
  A test-only future migration rolls back on pre-commit interruption; a committed
  upgrade preserves every versions/heads/commands/watches row byte-for-byte.
  The older registry rejects its manifest and database. Restoring the verified
  prior backup into a new destination recovers exact records and unknown-delivery
  history without another send; no post-upgrade writes are merged.

Initial test drafts addressed the claim's supersession at the wrong nesting
level, passed a stored receipt into insert, and bound the restored delivery
service to original-store ports. The tests caught these fixture errors; they
were corrected before the passing episode. A broad JavaScript edit also placed
an expected-semantics check in the list helper; cross-language tests caught it
and it was removed. Draft logs are not passes or production runtime findings.

Small raw receipts stay ignored under `data/validation/MAT-074/`:
