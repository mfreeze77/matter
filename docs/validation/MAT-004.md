## Transaction and payload evidence

The crash tests spawn real child processes and call `os._exit`, bypassing Python
cleanup. After termination before receipt or before SQL commit, the observation,
source index, command journal, and operation receipt are absent. The already
published immutable blob may remain unreferenced; retry can use it to commit a
complete operation. After termination following commit, restart recovers the
entire original journal and result, without rerunning payload checks.

A separate postcommit exception test returns `E_STORAGE_UNAVAILABLE` for the
lost acknowledgement and recovers the original success on exact retry. A
payload-store outage leaves no SQL observation, projection, or journal. These
are explicit persistence failures, never semantic duplicates or successful
empty source histories.

Two pairs of spawned writers race from the same prepared state: one pair creates
a previously absent source family, and one appends to an existing index revision.
In each race, one complete operation commits and the loser receives a durable
revision-conflict receipt. A new command prepared against the winner converges
to the original observation as a duplicate without another index revision.

Payload tests preserve non-UTF-8, empty, and Unicode-normalization-distinct bytes.
Publication uses a synchronized staging file and a non-replacing link; four
forced concurrent publishers leave one verified complete blob. Tests inject
prepublication file-sync and postpublication directory-sync failures, verify
that no partial file is presented as a payload, and prove retry cannot repair
or overwrite corrupt original content.

A database-only restore preserves the full original observation, command, and
receipt while an empty payload root reports unavailable bytes. Reusing the
retained scoped payload store supplies the original bytes without modifying
restored metadata. A separately receipted but incorrect source-index projection
is refused during history/preparation instead of producing a false duplicate.

## Reuse and independent review

Inspected the ticket-pinned
[StateCivics `matters.py`](https://github.com/mfreeze77/state-civics-ai/blob/a34fcec27f353187e7a23d54788b203d13ac87c1/services/local-accountability/sar_tracker/core_import/matters.py),
particularly `digest`, `same`, and `replace_scope`. The reused discipline is that
unchanged evidence keeps its old valid citation and avoids an evidence write.
Matter uses its existing strict canonical encoding and transaction/projection
port. Civic interpretation, reviewed-row policy, and complete-snapshot
retirement were not imported into incremental observation intake.

An independent contract and implementation review verified the evidence
comparison fields, receipt roles, source-family membership, append-order
supersession, frozen preparation, payload publication, and knowledge queries.
Review and tests identified and corrected four concrete boundary issues:

- Reused revision IDs must explicitly supersede a predecessor from that revision;
  citing a different revision alone cannot bypass a source conflict.
- Payload semantic errors must survive their `ValueError` inheritance instead
  of being remapped to storage outages.
- Direct time-bearing fragment validation must use the same Gregorian calendar
  checker as complete commands.
- Failure `affected_references` must use the declared bare entity-reference shape;
  exact prior pins remain in the journal's checked read set.

## Qualification limits

Host admission, authentication, truthful source classification, and appropriate
scope grants remain host responsibilities. A derived summary is validated as
declared lineage; no content classifier is claimed. Source text cannot mint
controls or confer authority through this handler.

Payload storage is separate from SQLite and requires its own backup or retained
immutable directory. Interrupted commands can leave harmless unreferenced blobs;
garbage collection is deferred. The reference file store assumes a
host-controlled local filesystem. Python does not provide portable directory
fsync on Windows; local execution used Linux and the configured CI jobs use
Linux. Process death and injected sync failures do not establish physical-power-loss behavior.

The added optional ingest result field requires earlier closed-schema readers
to update their schema, as documented in [compatibility](../contracts/compatibility.md).
Database migration format remains at version 1. General coverage/absence and
temporal dependency semantics remain MAT-010; continuing matter identity,
occurrence grouping, and claim/citation behavior remain MAT-005 through MAT-007.
