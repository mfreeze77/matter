# MAT-018 validation receipt

## Implemented scope

MAT-018 adds independent immutable purpose, objective, audience, responsibility
and preference definitions, exact stored versions/current pointers, explicit
component consumption and interval dependencies. It adds acknowledgement,
deferral, rejection and decision dispositions scoped to an exact matter,
purpose/audience version and subject snapshot, with expiry and explicit
authorized supersession/withdrawal.

Both mutation services use the existing trusted `record_control` operation,
authority service, SQLite transaction/receipt/replay guard and projection
history. Control fences are restricted to the exact public context/disposition
slot; complete public input targets are independently authorized and READ-audited
at prepare, commit, read and replay. Target traversal reuses `command_targets`,
including public references nested in typed payloads. Evidence and matter
identity are never rewritten by a context or disposition.

Eight internal schemas bind definitions, mutations, exact versions/current
pointers, disposition slots and retained control targets. No core record/command kind, storage backend,
migration, provider client, directory, UI, scheduler or delivery implementation
was added.

## Reuse and limitations

Read the canonical MAT-018 ticket, README, lifecycle/core/rules contracts,
`matterbrainstormspec` audience/purpose examples, existing profiles/component
references, controls, assessment publication, dependency registration, canonical
encoding and packaged schema facilities. Intent-graph `ticket_context` was
current at `c755dd991a9323fa89419a2f9a02aee011f6098b` and reported no prior
addressing commits or code citations. No cross-repository state was changed.

Linked context components are explicit exact references, not implicit latest
lookups or a recipient directory. Context capture exposes only selected
dependencies; consumers must bind them and their interval guards to the actual
assessment/rule/projection. Absence of an unselected disposition is not a complete
global query. Hosts must derive their exact candidate slots and preserve the
applicable original control-fence guards when a result depends on absence.

Responsibility declarations and preference budgets are data, not capability
grants or atomic budget reservations. Decision meaning and lifecycle transition
authority remain domain-owned. This module does not independently choose or
deliver attention treatment, cancel transport, run scheduled jobs, qualify a
provider, or infer source truth from a human acknowledgement.

These are synthetic behavioral and interface checks. No live provider, private
corpus, external directory, real human delivery, downstream integration,
