# MAT-016 validation receipt

## Implemented scope

MAT-016 adds explicit scoped dependency manifests, reverse/query watches,
atomic transitive invalidation, revision/epoch freshness and recomputation
tokens, original control/source READ guards, and a bounded immediate-control
fallback. It uses existing storage transactions, projections, exact-key
watches, source catalogs, typed predicates, candidate catalogs, negative
registrations and controls. No replacement storage, broker, scheduler or
delivery pipeline was introduced.

The trusted constructor-installed SQLite observer receives actual before/after
writes and typed core notices before receipt/commit. System reads are scoped
and journaled without rewriting caller command bytes or checked read manifests.
The narrow MAT-015 adapter registers actual stored judgments/assessments/current
lanes and changes only their registered validity/current-lane state. Host queue
projections retain their payloads; no physical dispatch cancellation is claimed.

## Executed focused checks

On 2026-10-27, the constrained repository Python 3.12 environment ran:

```bash
.venv/bin/python -m unittest discover -s tests -p test_dependency_invalidation.py -v
```

All **25 behavioral integration tests passed in 20.177 seconds**. They exercise
real scoped SQLite, actual core services and actual published MAT-015 graphs.

- AC-1: coverage-backed empty-scope watches and independent typed query watches
  retain current state after nonmatching arrivals. A matching observation whose
  identity did not exist at capture invalidates registered descendants inside
  the intake transaction. An indeterminate event-time arrival cannot become
  an unrelated/no-match outcome.
- AC-2: actual occurrence membership correction invalidates the exact recurrence
  projection, claim view and queued descendants, while an independent observation
  view remains current. Every source/registration revision and host payload
  remains historically readable, and derivative revisions share the correcting
  operation receipt. Actual immutable ClaimService and ObservationIngestor
  corrections likewise invalidate old-snapshot consumers without rewriting the
  old source assertion/bytes.
- AC-3: an audience-context revision invalidates only its dependent attention
  branch. Another audience branch and the independent evidence result remain
  current.
- A new candidate-set publication invalidates a prior uniqueness result. A
  considered candidate's own metadata revision invalidates it even before
  catalog republication; considered member/basis dependencies are indexed
  explicitly rather than watching only the set's revision.
- Actual source READ denial invalidates read-required work and descendants.
  Separate READ-fence capture retains the original host token unchanged. The
  actual MAT-015 preparation rejects a token that omits a selected source from
  its assessment scope; a freshness registration is not an authorization grant.
- The actual MAT-015 stored judgment, assessment, current lane and a registered
  host queue descendant invalidate transitively. Republication after correction
  replaces the invalidated lane once. An explicit audience-version supersession
  keeps its new lane fresh and invalidates the prior lane's queued consumer.
- Exact intake retries do not repeat invalidation. Further distinct matching
  arrivals advance an already-invalid registration's epoch while preserving one
  pending-recomputation flag. A recomputation racing another correction cannot
  publish as fresh. A bounded current reason tail retains earlier full reasons
  in immutable projection history without blocking future arrivals.
- Freshness tokens refuse historical registration/context state. Query freshness
  also detects a matching arrival through an explicitly unconfigured privileged
  store handle, even when that handle omitted proactive validity updates.
- Independent next-check and expiry deadlines are accepted and stale at the
  earlier reached bound. Cycles and foreign-scope dependencies are refused.
- An actual over-capacity `ControlService` READ denial still commits. A small
  scope generation fence makes earlier freshness tokens fail closed without
  pretending the full graph was individually traversed. After explicit READ
  restoration, recomputation can capture the new control/fence state and recover.
  A second unrelated operator-control fallback fences a recomputation already
  in flight.

Three internal schemas bind registrations, freshness tokens and the scoped
fallback fence. No new core wire record/command kind or SQLite migration is
required. The generic observer and bounded system watcher port have their own
real-SQLite tests; combined regression, independent review and installed-package
evidence are finalized separately by the integration owner.

Every participating handle must install the observer for atomic transitive
validity changes. Read-time dependency guards cannot reconstruct unobserved
typed semantic notices from arbitrary privileged raw writes. Scope fallback is
conservative and can fence unrelated work in that scope. It does not recall
completed transport, run a scheduler, establish a source's truth/independence,
qualify a model or replace current host permission checks.

These results are synthetic behavioral and interface evidence. No live provider,
private corpus, downstream integration, production timing, empirical accuracy,
actual external delivery or live usefulness was executed.
