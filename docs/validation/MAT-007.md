## Claim identity, wording, and corrections

The claim service stores the exact subject, namespaced predicate, structured
value, ordered qualifiers, temporal applicability, attribution, version text,
and optional namespaced components supplied by the host. It does not extract
source statements, normalize their wording, or promote their content to controls.
Known applicability endpoints are checked for reversed order without discarding
fractional precision; unknown time reasons remain explicit.

Each claim and its lookup/correction projection commit together. A duplicate
requires the same scoped ID and exact canonical input. Changed input under an
occupied ID is a conflict, and different IDs preserve separate assertions even
when their text matches. The original source bytes remain in the existing
observation/payload system.

A correction uses a new immutable ID and changed proposition-version label,
with distinct exact predecessors having the same subject and predicate.
Tests retain two competing branches and then append an explicit reconciliation
of both. Queries preserve the full connected history and all branch heads;
neither ID order nor version text chooses established truth. A separate claim
with the same subject and predicate remains outside that correction graph until
explicitly linked. Old claim pins, source wording, and old evidence targets are
unchanged.

## Citation precision and receipt boundaries

The included `Utf8LineLocatorAdapter` uses the existing local payload port. It
never fetches the declared URI. It validates exact source digest and optional
length, explicit whole-artifact source coordinates, strict UTF-8 passages,
one-based inclusive LF line ranges, and a nonempty quotation present within
the selected lines. CRLF, BOM, whitespace, case, Unicode normalization and
punctuation are preserved. A final LF adds no phantom line, and an empty
artifact has no selectable lines.

Whole-artifact citations are explicitly requested without a quotation and may
validate binary or empty payloads. Unknown coordinate schemas, excerpt-relative
source coordinates, unsupported text encoding and unsupported evidence kinds
remain unavailable to this adapter. Malformed known selectors, wrong URIs,
reversed/out-of-bounds ranges, wrong-line quotations and payload corruption are
invalid. A transient payload-store outage propagates as a storage error.

Preparation runs adapter I/O outside write transactions and freezes its exact
scope, evidence pin, content manifest, locator, quotation, adapter descriptor,
dependency pins, validation time, result kind and selected-byte digest or
failure reason. Every initial dependency is read and checked under the storage
command's revision guards. A failed validation remains in the command journal
and does not leave citation or relation children.

Successful creation atomically inserts the immutable validation receipt, the
relation, its exact query index, and the operation receipt/result. Stored
validation proves what was checked at that time. It does not imply continuous
payload access, authenticate a caller, or establish the proposition's truth.
The host owns adapter admission and operation authorization.

## Acceptance, dependency changes, and review findings

Acceptance revisions change only the acceptance descriptor. The claim, source,
relation kind, component, locator, quotation, applicability, provenance, and
validation receipt remain fixed. Identical acceptance is a no-op. Exact replay
returns the original command result after subsequent edits, while a fresh
duplicate creation returns the current relation and its original validation
receipt. Payload loss does not cause duplicate or historical reads to revalidate
bytes; a fresh relation ID must obtain its own validation.

The implementation supports both a mutable record's current revision pin and
its exact current snapshot-digest pin. A genuine stale snapshot produces a
durable revision conflict. Historical mutable adapter dependencies and provenance
parents retain their original pins in the immutable validation proof. Advancing
those records does not prevent the host from inspecting, rejecting or
superseding an old contribution. A new citation prepared before the same
advancement is refused as stale.

Independent review found and corrected two binding/compatibility issues: Python
dictionary equality could equate nested boolean and integer locator values,
and equality against the default revision-form pin could reject a valid mutable
snapshot-digest reference. Regression tests now exercise both distinctions.
Integration tests also caught malformed change-notice result arrays and a
missing acceptance revision increment; both were corrected before the final
suite. The stored-receipt path was separated from creation-time dependency
checks so historical evidence can still be retired. No material review finding
remains.

Change notices use the existing vocabulary and exact `before`/`after` arrays:
new model assertions or relations emit `new_evidence`, explicit claim corrections
emit `evidence_correction`, and acceptance revisions emit `disposition_change`.
Duplicates and no-ops emit empty lists. These records do not add an independent
source observation or run the MAT-016 invalidation engine.

## Concurrency, interruption, and restore

Two spawned processes competing to revise one evidence relation produce exactly
one updated revision and one durable conflict. The loser cannot overwrite the
winner, and both saved command results remain recoverable. A claim prepared
against a matter snapshot is refused after a concurrent metadata change rather
than silently refreshing its read set.

The interruption suite calls `os._exit` in actual spawned processes, bypassing
Python cleanup. Death before receipt or before commit rolls back a claim and
its index, or a relation and its validation receipt/index, with no command
journal. Retrying the exact command then commits the complete operation. Death
after commit recovers the original claim correction and dependency notice, or
the complete relation and frozen validation, without executing the handler
again. Acceptance and its query-index revision also roll back together.

Restart and verified new-file database restore preserve branching claim
histories, query watches, original and retired citations, every acceptance
revision, unchanged matter snapshots, and exact command replay. Payload blobs
keep the separate backup boundary established by MAT-004. These checks qualify
the local SQLite process-interruption path, not physical power loss or a
distributed backend.
