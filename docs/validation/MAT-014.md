# MAT-014 focused validation receipt

## Implemented boundary

MAT-014 compiles an exact typed profile graph, validates the union of required,
conditional and component dependencies, requires explicit consumed-output JSON
Pointer mappings, and executes independent ready-frontier nodes concurrently
through the existing MAT-012 evaluator. Exact input/result admission precedes
host dependent preparation. Deterministic explicit conflict policies retain
original disagreement and cannot bypass mandatory gates. Immutable diagnostics
retain actual inputs, uncommitted judgments/receipts, blocked/skipped paths,
currentness outcomes and separate resource reservations/invocation counts.

The implementation follows [canonical MAT-014](../../tickets/records/MAT-014.json),
the [rule contract](../contracts/rules.md), neutral core/lifecycle contracts,
`matterjevmesh`'s explicit-stage design and existing reuse boundaries. It reuses
`ProfileDefinition`, `RuleRegistry`, `SchemaRegistry`, `RuleEvaluator`, public
`prepare_input`, exact `admit_result`, and host currentness/control seams.
No provider, copied Oil runtime, workflow framework, alternative storage or
joint-probability inference was introduced.

## Executed focused checks

```bash
.venv/bin/python -m unittest discover -s tests -p test_rule_dag.py -v
```

The final focused run, including final-edge, budget-remainder, precedence
preflight and stop-query remediation, passed **31 tests in 1.820 seconds**. This receipt claims the observed focused
outcomes below, separately from combined integration gates.

- **AC-1:** A two-stage binding actually reads the selected candidate revision
  from both its dependent proposition and the exact admitted upstream judgment.
  A changed consumed revision and a different same-rule judgment identity are
  refused before downstream invocation. Actual original input digests remain
  attached to node and upstream receipts.
- **AC-2:** Independent functions rendezvous at a real two-party barrier, proving
  concurrent invocation rather than merely concurrent-looking receipts.
  Swapping which worker finishes first produces identical explicit-precedence
  composition, preserving both disagreeing original semantic outputs. Default
  retain-conflict policy keeps both outputs inspectable while quiet.
  An incomplete installed precedence order fails in preflight with no host
  preparation or evaluator invocation, preserving the no-side-effect boundary.
- **AC-3:** Unknown qualification, an actual expired exact certificate,
  ambiguous semantics and timed-out attempts block required descendants before
  their host input callback runs. No skipped/blocked path fabricates a false
  semantic output. A known false applicable condition skips; insufficient
  evidence blocks.
- A deterministic clock advances past a source certificate's expiry only after
  its child actually executes. Final admission rechecks every declared required
  and conditional edge, blocks the completed descendant, and retains both raw
  attempts without reporting a completed graph. An initially false conditional
  skip also becomes blocked when its qualification expires before final
  consumption. Final edge checks are retained separately from each node's own
  diagnostic admission; a known-false condition cannot mask another blocked gate.
- Rejected caller-supplied node text is not echoed in plan errors; node-specific
  diagnostic paths use bounded positions rather than source names.
- Conditional cycles and malformed edge selectors/missing consumed-output
  mappings fail before evaluation. A host-unavailable staging operation yields
  a typed blocked receipt rather than fabricated persistence or authority.
- Two concurrent-ready nodes share one remaining call allowance, admitting one
  deterministic node. Zero input/output/time allowances prevent invocation.
  Incomplete source coverage withholds composition despite a large independent
  impact value; its fallback is correctly excluded from actual evaluator-call
  counts.
- Resource receipts retain the input ceiling as `admitted_budget` and compute
  conservative `remaining_budget` from consumed reservations and elapsed time.
  A one-call run reports zero remaining calls; chaining that remainder admits
  no second invocation. Per-packet evidence caps remain unchanged.
- Cancellation during an actual attempt is retained and prevents later host
  preparation. A completed per-rule result returned after the shared deadline
  remains an unusable timed-out diagnostic. Final predecessor currentness
  failure blocks already-executed descendants while preserving their attempts.
- Exceptions and non-boolean stop-query results fail closed as latched
  cancellation. Post-binding failures preserve the completed raw judgment,
  attempt receipt, and actual invocation count; an initial bad query prevents
  preparation/invocation. A failure in the final outer poll still returns all
  completed diagnostics. Fixed safe stop diagnostics exclude rejected callback
  content and exception text.
- Arbitrary claimed graph results cannot use the public `GraphRun` constructor;
  returned run values are detached and immutable internally. Independent
  prepared inputs from different host scopes cannot be combined.

Combined regression, repository checks, installed-package checks and independent
review are integration gates owned by the root agent; this focused receipt does
not infer their outcomes.

## Limits

The host explicitly supplies authorized fresh preparation/staging views and
original control contexts. The focused staged read view is a synthetic fixture
with schema-valid stored-shaped judgments, not evidence of durable production
staging. No assessment is published and no action callback is available.
MAT-015 owns atomic publication/cache admission; MAT-016 owns general transitive
invalidation, including graph condition dependencies.

Shared reservations are conservative declared envelopes, distinct from actual
invocation counts and unmeasured provider usage. Python worker threads and host
callbacks must cooperate and use safe handles; the executor joins workers and
cannot preempt a blocked function or provide a memory/process sandbox. These
offline checks do not establish provider semantic accuracy, distributed timing,
production availability or live usefulness. See the [composition API](../composition.md).
