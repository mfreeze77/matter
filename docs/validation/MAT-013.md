# MAT-013 validation receipt

## Implemented boundary

The implementation adds a packaged closed profile schema, immutable exact
profile definitions and historical registries, component-specific semantic
fingerprints/read sets, explicit host admission ceilings, declarative graph and
resource validation, detached assessment input bindings, descriptive compatibility
reports, and non-mutating policy-supersession notices. Existing MAT-012 rule,
schema, canonical-data, and certificate applicability code is reused; no provider,
replacement storage, network retrieval, migration, or domain runtime was added.

The implementation follows the [governing contract](../contracts/rules.md),
[canonical MAT-013](../../tickets/records/MAT-013.json), neutral ownership decision,
and existing [reuse boundaries](../reuse/semantic-evaluation.md). No third-party
source code was copied. October 16 research proposals do not add requirements.

## Executed focused checks

On 2026-10-27, using the repository's constrained Python 3.12 environment:

```bash
.venv/bin/python -m unittest discover -s tests -p test_profile_validation.py -v
```

**24 tests passed in 0.212 seconds.** These are behavioral synthetic checks,
not measurements of provider accuracy or production usefulness.

- **AC-1:** Same-topic and same-matter meanings with identical output schemas
  produce distinct rule/component/profile bindings. Outcome ordering,
  descriptions, rendering parameters, and preparation changes alter their
  semantic binding. A real `QualificationRegistry.classify` check accepts an
  old exact certificate for its original rule and returns `mismatched` for the
  changed same-shape rule.
- **AC-2:** Exact-path refusals cover missing rule versions, undefined labels,
  incompatible output schemas/statuses, denied capabilities/scopes, proposal
  implications beyond the component ceiling, missing conflict resolvers,
  missing required outputs, absent/cyclic dependencies, undeclared cross-component
  reads, and each impossible calls/bytes/evidence/elapsed budget dimension.
- **AC-3:** Independent audience cadence changes preserve evidence fingerprints
  and read sets; an explicit audience dependency correctly propagates the change.
  Profile-level required-output, incomplete-evaluation, description and resource
  changes cannot claim semantic equivalence merely because components match.
- Two concurrent profile bindings retain the same matter pin and distinct profile
  pins. Public/input mutations cannot rewrite definitions, registry history, or
  old bindings. Supersession preserves both exact versions, returns a policy
  notice, and forbids same-version replacement. Source text remains data, and
  invalid declarations produce safe paths without echoing source content.
- Lifecycle extension declarations use the exact schema registry and reject
  invalid values or placement outside the lifecycle component.

Combined regression, installed-package, repository projection/validation and

## Limits

Profiles are declarations admitted by a trusted host, not source-access grants
or action permissions. Graph execution is MAT-014; assessment publication and
atomic currentness are MAT-015; general invalidation is MAT-016. Supersession
returns a notice for the host rather than persisting an event or rewriting an
assessment. Resource checks cover declared envelopes, not observed latency or
budget reservations. Registry history is immutable in memory; durable policy
bundle distribution remains later work. The binding concurrency check establishes
no assessment-engine or provider qualification.
