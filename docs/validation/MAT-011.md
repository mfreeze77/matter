## Authority, currentness and restriction boundaries

Static policy binds exact actors, scoped target ceilings, declared capabilities,
control kinds and admitted host authority receipt pins. Stored receipt origin
and stage are checked; schema validity alone is insufficient. One-shot target
iterators are refused rather than consumed inconsistently. A nonempty narrow
token cannot authorize an empty scope-wide context.

Work tokens retain the complete applicable fence manifest, including explicit
absence of a target fence, exact governing control pins and the original policy
reference. The global sequence is explanatory audit order, not an accidental
dependency of unrelated work. The prepared command digest binds the original
token. The command's full body and expected read set establish its minimum
affected entities; supplying a narrower target list cannot omit a referenced
entity. Transaction-time checks prevent stale authoritative child writes.

Applicable restrictions are conjunctive across distinct original target scopes.
An A-only stop followed by A-only resume cannot remove a still-active A-and-B
stop. The same property is tested for capability denial and release. Within an
identical original scope, a shorter later restriction cannot weaken an earlier
longer or indefinite restriction. Release requires an exact current restriction
pin and matching original target scope. Temporary allow/resume controls refuse;
permanent explicit supersession is the supported release model.

Finite restrictions use a half-open effective interval. Passing the end permits
a newly captured token while the old active-state token remains stale. A
historical `as_of` cannot bypass a current stop. If the host clock regresses
before an already committed governing control's effective start, authorization
fails closed for both cancellation and capability denial rather than making the
restriction temporarily inactive.

Source namespaces cannot reserve the internal sequence, target-fence or hook
addresses. The shared SQLite insert gate covers all core-record creation paths;
ordinary observation intake also refuses the control namespace family.
Identity-aware projection reads fail closed on a legacy wrong-kind occupant
instead of inventing epoch zero. Unknown effect-schema versions are refused,
and older control fixtures remain structurally readable without silently
receiving the new effect semantics.

## Replay, recovery and hooks

Exact command replay returns a historical success or failure without rerunning
its domain handler. Present read permission is checked inside the same SQLite
idempotency transaction before the result is disclosed. A read denial blocks
both old success and old failure disclosure while preserving the original
journal. Cancellation alone does not erase historical results. A replay cannot
become a new dispatch or reapply a superseded stop.

Control identity tests distinguish exact command replay, new-command identical
control delivery, conflicting content under the same immutable identity, and
stale prepared control revisions. Reopening the database preserves controls and
fences. An injected pre-commit failure leaves no partial control effect; a lost
post-commit acknowledgement recovers by exact retry without duplicate writes.

Hooks are explicit post-commit work. Each attempt first reserves one durable
`started` receipt; two concurrent callers sharing an attempt ID invoke the
callback at most once. Success and caught callback failure receive separate
immutable outcome receipts. A started attempt is never blindly rerun; retry
requires an explicit new attempt ID. Storage failure during hook processing is
observable separately and cannot mask or undo the already returned durable
control result. Asynchronous replay guards are refused, and a guard must
synchronously authorize rather than return a Boolean-like substitute.

## Independent review and qualification limits

Independent read-only review reproduced concrete authority and restriction
failures during development. The fixes now have regression coverage: one-shot
target exhaustion, empty-context widening, shorter-expiry replacement, overlapping
scope release, expiring release, reserved-identity poisoning and wrong-kind
projection lookup. The reviewer independently passed the then-current 16-case
control integration suite and additional ephemeral overlap, expiry, restart,
replay and source-spoofing probes. That historical review result is distinct
from the final 30-case targeted run recorded above.

The local host remains responsible for authenticating its transport, constructing
the static policy, keeping raw storage privileged, declaring all domain reads,
deriving complete delivery targets and integrating the dispatch seam. General
authority does not replace the existing association, merge or relation policy.
Literal target refs are not expanded through redirects or semantic hierarchy.

The immediate control lane is independent of evaluation and budgets; SQLite
`BEGIN IMMEDIATE` can still wait for another writer. Running Python work cannot
be forcibly stopped by this library, so cooperative hooks supplement durable
epoch fencing. An interrupted hook can remain `started`, meaning outcome
unknown; exactly-once external effects are not claimed. No outbox, delivery
protocol, native messages, provider quality, live-agent usefulness, production
authentication or multi-backend parity is qualified here.
