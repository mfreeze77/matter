## Implementation boundary

SDK **0.1.0.dev22** adds optional `PostgreSQLStore` through a host-supplied
synchronous psycopg connection factory/lease. The common relational command
engine preserves SQLite's guards, canonical bytes, savepoints, receipts and
retry semantics. PostgreSQL supplies consistent snapshots, scope coordination,
checksummed migrations and explicit recovery verification. SQLite's migrations,
file format and online-copy APIs remain unchanged.

The host payload adapter is a synthetic conformance fixture, not StateCivics
implementation. It locates packets by `packet_hash`, reconstructs
`canonical_bytes(exact_material)`, verifies `source_digest` and byte length, and
keeps a scoped digest-to-packet association. `evidence_hash` remains the packet
identity hash. Raw responses use separate durable host-owned exact-byte artifacts.
There is no interim production mount, deployment code or file-backup plumbing.
Frozen schemas and conformance clients are unchanged from the merged base.

## Independent review and repaired findings

The first OpenCodeReview subscription run completed two rounds over all 18
selected files (`review-claude.json`). Its 12 comments included duplicates; ten
comments on initially untracked files lacked line positions, but no selected
file was skipped. Confirmed findings were corrected: safe trigger search-path
precedence, preserved SQLite instrumentation imports, deterministic watch-race
assertions, catalog normalization for short/quoted schema names, host-selected
psycopg implementation, explicit identity-hash refusal and unused imports.

Separate fresh two-pass source reviews exercised the PostgreSQL boundaries and
identified repaired long-identifier index limits, broken command attribution,
orphan watches, stale generated index keys, host text encoding and internal
foreign-key trigger enforcement. The final follow-up verified all 16 internal
foreign-key triggers and the repaired regressions with no actionable finding.
Separate two-pass documentation review verified the pinned handoff and ownership;
its correction discloses the test harness's disposable database and privileges.

The pinned OpenCodeReview recheck completed two rounds over all 18 selected files
with no warnings (`review-pinned-claude.json`). It found missing direct database-
guard tests and a misleading invalid-`initialize` message; both are corrected.
The new guard test isolates each guard from alternate constraints, asserts SQLSTATE
23514 and unchanged rows, and verifies trigger settings after rollback. It passed
on every server major and the installed wheel. A separate two-pass review of the
claim-test supplement was clean (1/1 selected file, no warnings,
`review-claims.json`). Final two-pass review of the guard/message delta covered 2/2 selected files
with no findings or warnings (`review-final-fixes.json`). The separate two-pass
receipt review confirmed test attribution, hashes, ownership and activation
limits; it did not rerun the tests. Final canonical-record OCR covered both
selected JSON files in two rounds with no findings or warnings
(`review-records.json`); the generated Markdown/index and final completion
wording also passed the separate two-pass receipt review.

Codex bridge attempts reviewed zero files:
one failed config serialization, one requested an unsupported default model,
and the configured-model attempt was denied access to its review MCP tools under
its noninteractive approval policy. These attempts are not clean-review evidence;
no approval or sandbox restriction was weakened to work around the denial.

Diagnostic test failures remain in the local logs. A canary caught an early
adapter accidentally reusing SQLite; those runs are not PostgreSQL evidence.
An affected-row assertion caught an incorrect corruption-test namespace. One
installed runner invoked from stdin could not spawn its test processes; using
an importable runner produced the recorded 104-case pass. These were corrected
before counting their respective acceptance results.

## Storage budget and unrun acceptance

Starting free space was about 75.8 GiB, with a task budget of 10 GiB and a 50 GiB
reserve. Cached PostgreSQL 15/16/17 images used task-owned `matter-mat092-*`
containers with 512 MiB tmpfs data limits. At resumption, free space was about
68.6 GiB; earlier test containers and unfinished processes were gone. The three task-owned
PostgreSQL containers were recreated for the final server matrix. No real rehearsal data,
credentials or provider corpus was copied. All three task containers and both
disposable installed environments/copied fixtures were removed after their
checks passed. Retained receipts, runners and wheels occupy about 2.9 MiB; global
free space at cleanup was about 64.7 GiB, above the 50 GiB reserve. No other
container, rehearsal, cached image or downstream checkout was changed.

Unrun: StateCivics' actual payload adapter, authorized connection/place mapping,
backend/worker coordination, connected recovery with real host records/receipts,
and production activation. Encryption remains KS-637/KS-1152; dispatcher and
activation remain owner work. The host SDK pin is unchanged. No live provider
calls, empirical qualification or live-usefulness evidence were added. Physical
power-loss, replication/failover, all server minor releases and all Python/platform
combinations are untested. The existing SQLite rehearsal remains intact and
external to this repository.
