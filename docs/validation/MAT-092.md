## Review disposition so far

A fresh two-pass source review found and reproduced two issues: raw text btree
keys rejected valid long identifiers, and restore verification missed command
attribution/orphan watches. Fixed with bounded generated index keys plus exact
text comparisons, and journal write-pin/receipt relationship verification.
Follow-up review found stale generated keys could hide rows from the verifier,
and a host Latin-1 connection could reject valid Unicode IDs. Fixed with a raw
exact-text scan that independently recomputes generated keys, and transaction-local
UTF-8 with host settings restored. The final two-pass follow-up found no further
actionable defect and exercised the repaired boundaries on real PostgreSQL.

The first corruption regression contained an incorrect receipt namespace; its
rowcount assertion caught the ineffective injection. Corrected before the final
90-case matrix. These diagnostic failures are retained and are not counted as
successful acceptance runs.

Separate two-pass documentation review confirmed the pinned handoff, ownership
and digest mapping. Its one finding—failure to disclose the disposable restore
database and create/drop privileges—was corrected in the guide.

The first OCR Codex bridge attempt reviewed zero files because its generated
MCP environment override failed CLI config parsing; its warnings are recorded
in `review.json`. The normal subscription bridge is running with the default
two rounds; its final coverage/findings will be recorded before closeout.

## Still outside this acceptance

StateCivics must implement its host payload adapter, supply authorized connection
and scope mapping, connect backend/worker coordination and verify a recovery set
with its actual host records/receipts under KS-1158. The real SQLite rehearsal,
connected StateCivics recovery and production behavior were not exercised here.
Encryption remains KS-637/KS-1152. The dispatcher and owner activation are separate.
No host SDK pin was changed. No live provider call, empirical qualification or
live usefulness evidence was added. Physical power-loss, replication/failover,
all PostgreSQL minor versions and all Python/platform combinations are untested.


The completed first grouped OCR reviewed all 18 selected files in two rounds.
Its only coverage warning was that ten comments on initially untracked files
could not be line-positioned; no selected file was skipped. The 12 comments
included duplicates. Confirmed issues were repaired: trigger search-path
precedence, SQLite instrumentation aliases, deterministic negative-watch
contention, catalog normalization of short schema names, host-selected psycopg
implementation, explicit identity-hash refusal and unused imports. A follow-up
integrity audit added all 16 internal foreign-key trigger definitions/states to
the verified manifest. Its final two-pass review and targeted PostgreSQL checks
found no further actionable issue.

The final full run uses the frozen runtime/schema files. Three unused test
imports were removed during that run; test bodies and runtime bytes did not
change. Their prior hashes remain in `source-manifest-final.json` for an honest
record of the source at test start. One installed test-runner invocation from
stdin could not spawn worker processes; `installed-postgresql-final2.log` is
therefore a harness failure, not acceptance. Running the same installed cases
from an importable script passed all 104 checks in 46.437s.
