## Authority, relationships and current identity

`RelationPolicy` and `MergePolicy` admit actual immutable host-origin authority
receipts. Actor, scope, policy digest and correction capability are independent
gates. An evaluator declaration or existing accepted association cannot grant
merge permission. Equivalence basis pins are audited and checked for actual
existence/currentness; their semantic conclusion remains a host decision.

Relationship rules freeze kind, version, directionality, self-link permission
and acyclicity. An edge cannot lose its constraint through a later permissive
rule version. Effective graph validation resolves complete current identity
groups while retaining each raw endpoint. Repeated identical declarations keep
the original edge. Graph traversal and corruption failures never become an
empty graph or a successful partial operation.

Each original matter has either no group projection, meaning untouched
singleton, or a verified complete mirror. Every mirror names the same direct
survivor, complete member set and immutable decision. Merge/correction advances
all affected matter and mirror revisions together. Explicit revision and digest
pins remain guarded. Raw historical reads keep original snapshots; current
resolution follows only these explicit identity decisions.

The integration tests prepare a command and then alter metadata, add a new
child, insert the first blocking disposition, or publish another identity
decision. Execution refuses stale/phantom reads without partial redirects.
Earlier association acceptance becomes stale after its exact matter inputs
change. A redirected original cannot receive a metadata edit that silently
changes survivor semantics.

## Correction, separation and release

Correction plans retain every original identity exactly once. Shared children
remain in each partition containing an original owner, without cloning source
records or inventing corroboration. Missing/duplicate identity members and
omitted children refuse. New claims after preparation invalidate the plan;
new claims or metadata present before a fresh plan are preserved.

Undo uses the governing merge's actual before-partitions, including prior
multi-member groups. A split may select a different exhaustive partition.
Correction creates symmetric protection for every cross-partition original
pair. The merge guard checks all original members of every operand, including
both protected members hidden behind other representatives. MAT-008 blocked
merge dispositions remain independently effective across relation versions.

The explicit `release_identity_separations` operation requires current
protected pins, admitted correction authority, evidence, reason and merge
policy. It changes only selected barriers and an immutable release receipt.
Matter/group revisions, source records, attachments and derivative validity
remain unchanged. Fresh merging must still satisfy all remaining guards.
A later undo can create protected revision 3 after release revision 2; replay
of the old release returns its saved result without weakening revision 3.
Selective release does not remove other universal or MAT-008 protections.

## Registered validity and immutable history

A trusted host can register an assessment or host projection against complete
exact identity dependencies. An assessment must retain those dependencies in
its positive manifest. Missing original matter dependencies, unrelated extra
dependencies and historical registration snapshots that bypass a current
replacement are refused.

Identity changes invalidate current registered work inside the same transaction
as matter/group changes. The historical assessment record, original positive
manifest, former group snapshots and source pins remain available. Tests check
both the current validity refusal and the unchanged historical merged view.
Within a consistent snapshot, the current-validity gate cannot accept an old
registered result after the corrected groups commit. Historical registration
snapshots remain readable. Rollback restores both sides together.

The inventory composes existing exact-key, claim, citation, accepted-association,
relationship and registered derivative indexes. Arbitrary custom storage writes
are not automatically assigned owners. Old cited occurrence snapshots remain
historical rather than being silently refreshed to current membership. Hosts
must use the explicit validity gate; the hook is not general transitive graph
invalidation or delivery cancellation.

## Independent integrity review

Review reproduced and corrected concrete integrity gaps before final acceptance:

- Current identity readers now refuse a member revision older than its governing
  decision even when the mirror declaration itself looks consistent.
- Registered dependency readers verify complete original identities, allowed
  dependency kinds, and the actual current registration before accepting it.
- Malformed watched projections produce typed evidence failures; actual backend
  and revision failures retain their original codes.
- Historical identity views bind claimed group/validity/protection writes to
  their actual committing operation receipt. Copied receipts cannot claim
  another command's old snapshots.
- Correction proofs require all cross-partition protections and a direct
  governing merge. Metadata may advance without invalidating legitimate history,
  but a correction chain cannot induce recursive ancestry traversal.
- Release proofs require the cited correction to record exactly the protection
  revision being released, with its exact predecessor. Merely listing a later
  protection pin is insufficient. Release history also checks actual commit
  ownership while repeated release/re-protection proof reads remain bounded.

## Reuse and qualification limits

The ticket-pinned civic
[matter importer](https://github.com/mfreeze77/state-civics-ai/blob/a34fcec27f353187e7a23d54788b203d13ac87c1/services/local-accountability/sar_tracker/core_import/matters.py)
was inspected at `a34fcec27f353187e7a23d54788b203d13ac87c1`, especially
`CHILDREN`, `merge_blocker`, `merge`, complete-group protected undo, direct
redirect repointing and moved/retained collision receipts. The neutral design
reuses those distinctions with Matter's existing immutable records, private
projections, exact revisions, scoped storage and association proof readers.
No civic SQL or runtime code was copied, no upstream test suite ran, and no
external repository or deployment changed.

The supported limits are 128 affected original matters, 4,096 retained child
references and 4,096 relationship graph records. Exceeding a bound refuses
rather than truncating a group or inventory. Scope is the bound storage scope;
cross-scope merge grants are not implemented. Relations support active creation
and identical duplicates; generic revocation/rule migration remains future work.

Semantic equivalence proof, evaluator/provider accuracy, general host control
epochs, transitive invalidation, assessment execution and delivery remain later
tickets. Twelve core record kinds, wire version `1.0`, canonical encoding and
SQLite migration are unchanged. New private schemas and additive fields require
older closed-schema readers to update; no compatibility fallback is claimed.
