## Acceptance and failure cases

AC-1: actual scoped SQLite start/completion and cache reuse retain the original
immutable execution receipt while recording a distinct reuse observation. Changing
run/batch IDs still produces exactly one observed adapter call. Repeating an
attempt does not resend; reopening the backend recovers an interrupted started
attempt as unknown. New receipts retain evaluator origin and unchanged source
pins; a retry is lineage, never an additional source occurrence or corroboration.
Zero allocated retry capacity refuses a new dispatch.

AC-2: concrete/requested model, adapter/transport, packet, ordered question set,
ordered Score rubric/Choice options, renderer and precision mutations change
exact identity. Missing concrete resolution disables lookup. Correlation IDs
remain conservative exact matches, and answers are never remapped. Logical IDs,
physical IDs, dispatch deadlines and token capture timestamps are outside semantic
reuse identity. Actual stage plan/transforms and stored parent pins remain bound.

AC-3: a real failed batch retains its valid diagnostic head plus missing-head
faults through storage/replay and cannot populate the reusable entry. Tampering
with evaluator origin or promoting primitive admission is rejected after
recomputing the corresponding normalized hash. Opaque dispatch failure retains
an unknown result and its exact request without a fabricated zero-call claim.
Actual StageRun null results are persisted as already-observed unknown evidence,
not misrepresented as a predispatch claim. Cancellation during an adapter call
refuses completion publication while its durable operation journal preserves raw
artifact references and diagnostic inputs; no automatic resend follows.

AC-4: persisted/reloaded/replayed high-precision proposition probability retains
0.1234567890123456789 exactly. An actual fractional Score0.7 retains ordered
legend, confidence0.1234567890123456789, distribution residual-0.1 and Score
residual0.1 under the independently trusted nearest-rounding profile. Original
native and neutral bytes are separately restored unchanged. Equivalent decimal
spellings share canonical normalized digest while original wire digests differ;
a rounded binary-float reconstruction does not match the original byte artifact.
Missing byte/token/price measurements remain null with explicit reasons.

Present source READ denial blocks history and cache lookup; ordinary subject
revision blocks reuse while preserving inspectable historical bytes. Protected
packets without the installed boundary fail with the access-specific error before
any adapter call. Installed policy requires the same original work token and
actual provider/transport. The effective dispatch deadline is clipped to actual
remaining allocation and survives idempotent recovery from the original submitted
request. Qualification callbacks are rerun during lookup, preparation and the
atomic reuse writer: revocation between lookup/writer refuses reuse without a new
provider call or altering the original receipt. These use synthetic classifier
outputs, not a claim of real certificate qualification.

## Practical limits

The injected provider remains cooperative; no exactly-once remote execution or
Python preemption is claimed. Conservative caps stay charged after unknown or
failed work. Full protected packet/context identity and optimistic concurrent
cache publication can conservatively miss/refuse reuse; hosts create a new
attempt to capture changed state. Original result timing stays historical, so
new call counts use observation phase/`dispatched`. Historical replay is not a
fresh qualification decision. The host packet producer, current concrete-model
binding and explicitly installed classifier remain trusted; this store issues no
certificate and grants no action authority. Real provider accuracy, held-out
calibration and useful live behavior require separate later evidence.

## Existing-attempt context remediation

Read-only integration review reproduced a consumer-context defect: after actor A
completed an attempt, the same IDs/request accepted actor B's actual assessment
token despite B having no READ scope for A's source; foreign allocation, changed
parent/retry references and a different access context were also ignored. New
attempts under B correctly failed, so the exception was specific to historical
recovery. No source was changed during that reproduction.

The bounded fix compares supplied original token/access context and normalized
parent/allocation/retry lineage against the actual retained observation before
returning history. Different consumer context fails authority; changed work
lineage fails idempotency. Cache-satisfied requested retries now preserve their
actual `retry_of` value. No history is rewritten or redispatched.
