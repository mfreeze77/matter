## StateCivics handoff: two distinct inventories

Reuse the existing host, grants, controls, packet factory, dispatcher and sink.
No new identity, retrieval, queue or storage service is supplied.

1. Build **current evaluation roots** from the actual approved intent/context
   and selected source/event. Earlier captured assessments are history, not
   current host-rule inputs. The existing rule remains deterministic and reads
   no model-derived labels.
2. For baseline reading, use current roots plus the actual prior assessment
   root. In the existing store snapshot call
   `matter.access.source_access_provenance(view, roots)` to obtain exact grant
   candidates. Authorize every candidate against real host ownership and READ/
   audience/provider/source policy. Preserve the old context pins; also grant
   their current heads. Never rebind old pins to the new revision.
3. Build policy from those authorized grant candidates. Pass **roots**, not the
   expanded grant list, to `access.capture`. A context used to read history can
   include the prior assessment root. Pass current roots and a separately
   captured current-root access context to `AssessmentService.prepare`; do not
   nominate the prior assessment or its old contexts as current rule inputs.
4. Retain the existing MonitoringHost/HostMonitoringState and monitoring 1.0/
   1.1 request/result shapes. The SDK can emit AccessContext encoding **1.1**
   when both old/current metadata snapshots are needed. Install the new SDK in
   every participating process before reading that new state; keep the existing
   receiving images for the separate MAT-083 investigation.
5. On a fresh isolated store, rerun the actual KS-1126 dispatcher timeline:
   capture → approved edit → later same-subject capture, then ten labelled
   synthetic corrected printings with per-step prepared sizes. Real comparisons
   remain real; authored printings must not masquerade as legislative versions.

Both grants remain mandatory, current heads remain fenced, stale current roots
still refuse, and historical bytes are integrity checked. Full exact inputs
remain in the durable journal; old records are readable and are not rewritten.
Already oversized legacy history can still exceed the budget. Downgrading new
state to dev19 is unsupported; no rollback of the shared stack is performed.

Package/source pins and final checks will be appended at release. StateCivics
owns its host update, receiving image and actual timeline acceptance. The
SuperTokens opt-in, cadence, KS-1152 choice and production read remain unapproved
and unperformed here. No real-client data or provider calls were used, and no
qualification, production send or activation is claimed.
