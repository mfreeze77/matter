## Design and reuse decisions

The ticket's pinned Oil source was inspected at
`3d7c629fd45067de405c1bbae0a2aa0e4036399a`:
[`CognitionStore.transaction` and `RunStore.commit`](https://github.com/mfreeze77/oil/blob/3d7c629fd45067de405c1bbae0a2aa0e4036399a/src/intent_oil/cognition_store.py).
The implementation reuses the checked-read transaction design without importing
Oil's run identities, state classes, model results, or delivery logic. It adds
exact original-result replay, atomic migration markers, and cleanup for failures
raised by commit itself.

The reference backend deliberately verifies `DELETE` journaling, `EXTRA`
synchronization, and foreign-key enforcement. It uses one private connection
per operation and explicit `BEGIN IMMEDIATE`, shared by Python 3.11 and 3.12.
Long read snapshots can block writer commit; the tested behavior is explicit
unavailability followed by an unchanged-command retry after the reader closes.
SQLite's [transaction documentation](https://www.sqlite.org/lang_transaction.html)
and [synchronization guidance](https://www.sqlite.org/pragma.html#pragma_synchronous)
support this choice. Migrations execute complete statements separately because
[Python's `executescript` can commit a pending transaction](https://docs.python.org/3.12/library/sqlite3.html#sqlite3.Cursor.executescript).

Independent review found and corrected these concrete issues before publication:

- Snapshot-only history and journal methods were explicitly refused on the
  transaction object to close an undeclared-read route.
- Returned failure results now use the same affected-reference scope filtering
  as raised semantic failures, before result hashing and journaling.
- Ownership probing uses an exact `sqlite_` prefix; a foreign table resembling
  that prefix cannot cause its journal settings to change before refusal.
- Very large, nonfinite, and out-of-range lock timeouts produce safe schema
  errors. Copy deadlines are separate from the valid zero-lock-wait setting.

Each correction has a focused regression test. Final independent source review
found no remaining material issue in the MAT-003 scope.

## Reproduce and interpret the evidence

```bash
python -m pip install -e . -c requirements-test.txt
python -m unittest discover -s tests -v
python -m matter render --check
python -m matter validate
node tests/fixtures/canonical/verify.mjs
python -m matter demo all
```

The [storage guide](../storage.md) provides an executable transaction example,
the API contract, retry/error behavior, migration rules, and backup/restore
commands. The installed-package section of the CI workflow reproduces the
release-package smoke check.

Actual `os._exit` tests establish process-interruption behavior, not physical
power-loss, disk-controller, or network-filesystem qualification. The port checks
reads performed through its API; it cannot establish completeness of arbitrary
external state read by a trusted Python handler. Backup/restore are whole-database
owner operations and preserve all scopes. The host supplies authentication and
operation policy. Generic alias values and exact-key watch registrations are
durable, while merge semantics and absence-predicate invalidation remain later
tickets. There is no claim of distributed consensus or exactly-once external
delivery.
