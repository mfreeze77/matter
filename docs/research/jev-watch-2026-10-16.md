# JEV research update — October 16, 2026

Status: research and implementation recommendations. This note adds four
developments published October 12–15 and proposed application relationships to
the [October 8 reuse review](../reuse/semantic-evaluation.md). External results
are author- or vendor-reported and were not reproduced for this update. Source
review does not qualify a model or complete an implementation ticket.

Repository baseline: [Matter at be2b652](https://github.com/mfreeze77/matter/tree/be2b652d116f4eab77fc9721ba45f545ddc40e26).
The [JEV contract](../jev.md), [evaluation contract](../evaluation.md), and
[ownership decision](../decisions/0001-core-ownership.md) govern implementation.

## Existing foundation and intended ownership

MAT-012 implements exact rule definitions, bounded evidence preparation,
deterministic and recorded bindings, prerequisite admission, and uncommitted
judgment/receipt inputs. Its registry currently admits only deterministic and
recorded modes. It does not invoke a live provider, issue qualifications, or
publish assessments. Its synchronous elapsed limit is cooperative, not a
preemptive provider deadline. See the [implemented API](../rules.md) and
[binding registry](../../src/matter/evaluators/base.py).

The typed semantic executor, question registry, provider transport, and broader
qualification work remain planned in MAT-026–045. The current certificate
registry checks exact declarations on a host allowlist; it does not establish
provider accuracy. These developments should extend the existing boundaries.

Matter owns neutral contracts and reusable core logic. OIL is the first intended
operational integration workload; its native adapter remains planned. Domain applications retain retrieval,
specialized extraction, accepted intent, calculations, and action authority.
The [existing reuse map](../reuse/semantic-evaluation.md#existing-oil-seams)
already identifies OIL's arbitrary-question transport and strict answer
validation as implementation candidates. Package extraction or a compatible
adapter remains an explicit implementation choice, with source and dependency
review at the selected revision.

### 1. VideoJev: proposed temporal evidence

VideoJev directly scores temporal grounding and multiple-choice video answers.
The authors released Apache-2.0 code and 4B/35B-A3B model artifacts. Their paper
reports mean-IoU gains of 6.7 and 10.8 points over the respective backbones and
2.8–3.1× faster grounding forward execution; video QA exceeds 100× versus the
tested Thinking-mode backbones. These are model-forward measurements, not
whole-pipeline latency. Evaluations use video frames without audio or subtitles.
Sources: [paper](https://arxiv.org/html/2610.18615v1),
[code snapshot](https://github.com/MCG-NJU/VideoJev/tree/0cfbd85c84eca19af007f72a69ce0f1df9878242),
[4B model card](https://huggingface.co/ZhuYuhan/VideoJev-4B), and
[35B-A3B model card](https://huggingface.co/ZhuYuhan/VideoJev-35B-A3B).

The inspected code is pinned above; the model-card URLs are discovery links,
not immutable checkpoint revisions. A future run must pin the actual weights,
processor, and code. The documented 4B environment was tested on an H200, which
does not establish a minimum hardware requirement or local-machine suitability.

**Recommended boundary:** a DIAT or other media adapter runs the experiment and
exports a derived result linked to the original recording. Matter can preserve
its relationship to a continuing question. Keep recording hash, original-clock
window, query, checkpoint, frame sampling, input preparation, raw scores,
proposed interval, omissions, and review state together. Validate temporal
locators in a domain adapter: the included MAT-007 citation adapter handles
UTF-8 lines and deliberate whole artifacts, not temporal video spans. See the
[citation API](../claims.md) and [DIAT profile](../profiles/diat.md).

Two implementation details affect the experiment. The inspected
[temporal decoder](https://github.com/MCG-NJU/VideoJev/blob/0cfbd85c84eca19af007f72a69ce0f1df9878242/videojev_hf/videojev_temporal.py)
returns a nonempty contiguous interval, including a strongest single position
when all positions fail the threshold. It does not supply a native absent-event
or multiple-event result for a single grounding query. The
[quick inference implementation](https://github.com/MCG-NJU/VideoJev/blob/0cfbd85c84eca19af007f72a69ce0f1df9878242/videojev_hf/modeling_videojev.py)
can reuse visual features, but that alone does not establish the paper's full
language-prefix caching behavior; the research also describes cached and joint
inference modes. Measure the exact path chosen.

Start with bounded clips and independent interval labels, including absent,
repeated, short, occluded, and ambiguous events. Measure temporal IoU, boundary
error, misses, false event proposals, and full decoding/preparation/inference
cost. A proposed vote interval does not establish what was said, the speaker's
identity, or an official disposition. Scores require task-specific evaluation;
the paper itself discusses overconfidence.

### 2. Sayora: evidence selection and explicit rejection

Sayora tested jev-1.13.0 on 168 model-generated questions across four customer
websites: 128 answerable and 40 unanswerable. The model selected from page
descriptions plus a none option. Reported results use different denominators:

| Measure | Denominator | Jev | Production embeddings |
|---|---|---:|---:|
| Correct first page | 128 answerable questions | 88% | 70% |
| Wrong handoff: neither of the first two returned pages answers | All 168 questions | 3% | 33% |
| Correct rejection | 40 unanswerable questions | 38/40 | 9/40 |

The 100-page shortlist's 95% first-page result and zero wrong handoffs apply
only to the 232-page site. Questions and most relevance labels came from
models; five judgments received manual checks. This was not a live-call trial
or a comparison against a full hybrid/reranking baseline. A documented false
none occurred when a page description omitted an answer present in the page.
Source: [Sayora's experiment](https://sayora.ai/many-hands/jev-vs-embeddings/).

**Recommended boundary:** EXAIS or another host retrieves eligible candidates;
the planned semantic layer evaluates a frozen packet with exact source IDs,
versions, locators, omissions, and declared coverage. Compare original excerpts
and descriptions as separate preparation variants. Report candidate recall,
incorrect rejection, unsupported handoff, irrelevant-source contamination,
omitted counterevidence, and downstream claim support. Sayora's wrong-handoff
definition does not measure every irrelevant source in a mixed handoff.

Preserve these distinctions:

- None of the supplied candidates is suitable; the searched corpus lacks the
  answer; and the event did not occur require different evidence.
- A lost detail in a description, an absent candidate, ambiguity, and execution
  failure need different recorded reasons.
- Generic passage selection belongs in retrieval/preparation. Matter's
  association API accepts observations, occurrences, and matters as members;
  it must not be repurposed as an arbitrary passage-ranking API.
- The initial association family has fixed same_matter, related, different, and
  insufficient outcomes. Dynamic candidate options require a separately
  specified and evaluated extension, including cardinality and order changes.
- Support, contradiction, and qualification can coexist across claim components.
  An exclusive Choice must not discard jointly necessary evidence.

The [association contract](../associations.md), [question contract](../jev.md#questions-and-rendering),
and [MAT-033](../../tickets/MAT-033.md) already establish these boundaries.

### 3. Liquid d1-ultra: compare the tested procedure

Liquid's October 15 launch reports a comparison with Jev 1.14 across 112
evaluations and claims stronger accuracy and calibration. The announcement
does not provide per-example outputs sufficient to reproduce that claim.
Treat it as a comparison candidate. The hosted model supports typed decisions;
shared primitive names do not establish equivalent behavior or qualification.
Source: [vendor announcement](https://www.liquid.ai/blog/d1-ultra).

The documented direct endpoint is
https://api.liquid.ai/decisions/v1/systemone. TypeSafe SDK examples cover text;
image examples use raw HTTP with a top-level Base64 images array. Each question
is billed for its own text and all supplied images, so a shared request does not
imply shared billing. Sources: [API/SDK details](https://docs.liquid.ai/lfm/models/d1)
and [billing](https://docs.liquid.ai/lfm/models/decision-models).

**Recommended boundary:** add d1-ultra to the comparison and capability matrix
for the planned neutral executor. Use identical semantic definitions and frozen
evidence, with explicit provider projections. Record unsupported capabilities,
requested/resolved model, raw response, adapter/precision version, attempts,
per-question usage, missing measurements, and actual cost basis. Do not transfer
a threshold or certificate between providers from their advertised calibration.

Matter's decimal contract is consequential here: preserve raw response bytes and
numeric lexemes, validate with exact decimal arithmetic, and normalize into the
declared decimal strings before receipt hashing. Converting binary floats to
strings is insufficient. A float-only SDK representation without recoverable
wire evidence must declare its precision limitation and leave exact-numeric
admission unqualified. Preserve native Noul probability separately from
Choice/Score distributions and confidence. See [numeric representation](../jev.md#numeric-representation-across-the-provider-boundary).

### 4. OpenRouter: qualify a distinct transport configuration

OpenRouter lists typesafe/jev-1.14 with TypeSafe as the provider and a 262,144-token
context configuration. Its TypeSafe-compatible route is POST /api/v1/systemone;
the separate Decisions route is POST /api/alpha/decisions. The SDK bridge
documents typed answers plus id, provider, and usage.cost. The TypeSafe SDK's
model-list method rejects OpenRouter's different Models API response shape;
use a supported discovery path. Sources: [model listing](https://openrouter.ai/typesafe/jev-1.14)
and [SDK bridge](https://openrouter.ai/docs/guides/community/typesafe-sdk).

The gateway documentation says more than roughly 32,000 text bytes or any image
triggers TypeSafe's experimental long-context mode, described as slower and less
accurate than the default mode. The threshold is bytes, not tokens. TypeSafe
documents a separate opt-in 262k configuration and experimental image support.
Sources: [gateway behavior](https://openrouter.ai/docs/guides/community/jev),
[TypeSafe models](https://docs.typesafe.ai/models), and
[Jev 1.14 announcement](https://typesafe.ai/blog/jev-1-14).

**Recommended boundary:** extend MAT-032's transport decision using the same
conformance suite and receipt contract. Check answer IDs, primitive shapes,
numeric preservation, image/header behavior, context-mode activation, errors,
model resolution, and usage. An alias with a familiar name cannot substitute
for an exact resolved model. Context mode and image preparation are execution
conditions to record and consider in qualification and cache reuse.

The gateway supplies another route to a model; repeating an answer through that
route is not independent source corroboration. New provider primitives such as
Box remain unsupported by Matter until their meaning, representation,
validation, and evaluation are explicitly implemented.

## Application relationships

These relationships describe ownership and proposed use. The existing profiles
are planning contracts, not proof of deployed integrations. EXAIS and CSCAi are
proposed profile extensions in this note.

| Application | Continuing question or proposed contribution | Responsibility retained by the application |
|---|---|---|
| [OIL](../profiles/oil.md) | Recurring operational issue, new evidence, recovery, and usefulness of another intervention | Accepted intent, existing runtime/storage/delivery boundaries, controls, and recovery policy |
| [StateCivics and crawler](../profiles/civic.md) | A case, instrument, or civic question across agendas, amendments, minutes, and corrections | Source collection, jurisdiction interpretation, reviewed receiver authority, and public presentation |
| [DIAT](../profiles/diat.md) | Speaker/procedure hypotheses, conflicts, original-clock evidence, and useful next checks | Private corpus, acoustic research, extraction, candidate pools, identity resolution, and enrollment |
| EXAIS — proposed | Evidence selection for a continuing research question, preserved sources, and changing evidence support | ACL-scoped retrieval, candidate discovery, graph/vector search, and source hydration |
| CSCAi — proposed | Drawing/specification discrepancy, unresolved legend ambiguity, or requirement change across revisions | Drawing geometry, accepted takeoff records, engineering calculations, pricing, and review authority |

For example, a synthetic CSCAi matter could ask whether a panel design satisfies
the project's revised requirements. A drawing revision, source manual passage,
deterministic sizing result, and operator correction would remain separate
observations or claims. Semantic judgments could identify support and remaining
conditions. Future assessments would bind the applicable policy and source
revisions; CSCAi would retain the engineering decision. An ordinary lookup or
device detection need not create a new matter.

Contracts can be shared without requiring every application to import the
Python runtime immediately. A language-specific adapter must preserve the
declared semantics and demonstrate compatibility. This note does not define a
new runtime dependency, create an application profile, or authorize a rollout
in another repository.

## Review boundary

This update records source findings, repository fit, and suggested evaluation
cases. It adds no provider calls, model downloads, runtime bindings, production
configuration, real evaluation corpus, ticket completion evidence, or automatic
state transitions. The October 8 source review remains historical evidence;
later implementation must recheck the exact upstream versions it selects.
