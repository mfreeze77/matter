# Decision 0002: bounded monitoring handoff version 1

Status: adopted for the capture-only component contract. The owner explicitly
approved a real user-owned watchlist/item target and refusal until it exists and
is authorized, then directed progress toward freeze and MAT-082. Approval is
not production alert authorization or approval of provider qualification.

The remaining dispositions below are bounded engineering choices under that
instruction. They are not a claim that the owner approved particular UI labels,
or that StateCivics has implemented the required host mapping. Host review inputs
are the owner's supplied main-code corrections, independently checked at
`e349713e6` and record correction `e2dcb04cc` through `8955f16d8`.

- **D1:** one jurisdiction; distinct record/objective scope; actual authorized
  candidate subjects at dispatch. A broad objective requires an owned watchlist
  and item plus real factual/audience event associations before evaluation.
  Reuse of one owned item for several objectives is allowed if the host verifies
  each association; deduplication includes intent/audience/material identity.
  No fake bill, empty foreign key or second capture sink. Host provisioning UX
  and migrations are KS-1122/1123/1124 work.
- **D2:** snapshot selected client defaults in the approved immutable revision.
  Linked future defaults are outside version 1. Explicitly revising values changes
  their consumed component versions; contact/general-note inheritance is excluded.
- **D3:** approved provision-specific proponent/opponent/neutral/unknown, with
  unknown for absent position. No inference from organization type or automatic
  expansion of a legacy whole-record stance. `monitor` remains following intent.
- **D4:** explicit subscriber-approved submission; drafts never evaluate. Main's
  create/revise/retire remain the reuse baseline; host draft/pause/revoke wiring
  still must be built. A missing active-from projects to the stored revision's
  approved-at; an explicit start is preserved. Missing end means no scheduled end.
  Controls and current approval remain authoritative. Save-button text and the
  mechanism for reactivation are host UX choices, not new wire states.
- **D5:** retrospective-selected, explicitly reconstructed rehearsal context;
  current context for incoming live. A scripted edit selects a new approved
  revision at its scheduled checkpoint. No historical-preference claim or future
  evidence. Real authorization/budget clocks remain current.
- **D6:** keep actual conveyed history. Ordinary novelty uses a host-verified
  purpose/subject/material-compatible baseline; do not relabel other-purpose
  output as absent or delivered. A linked correction may refer to actual older
  capture even after purpose edits, under current access. Already-handled applies
  to its exact contribution/subject, not every future deadline or correction.
  Rejection/deferral/undo use existing scoped dispositions and current pointers;
  no hidden expiry timer or automatic global feedback learning is added. Explicit
  current pause/revoke/cancellation always wins. A purpose-incompatible ordinary
  baseline is withheld for host reconciliation, not guessed or silently reset.
- **D7:** in-app capture only, at the host's explicit immediate/digest checkpoint.
  No inherited email/SMS/webhook destination. Current mute/ownership must be
  checked independently before explicit in-app selection. Live provider selection
  and call/time/byte/cost limits are explicit. Production delivery, multi-place
  aggregation, custom alert writing and qualification are separate work.

Version `monitoring-handoff/1.0.0` freezes wire shape and these semantics for
component implementation. It does not ship the host's missing lifecycle/access/
broad-scope/provider seam. A later incompatible decision needs a new version and
compatibility vectors. The contract lock pins the specification, this decision,
portable/installed schema and authored synthetic vectors. Their judgments remain
illustrations, not independently reviewed labels or runtime acceptance.
