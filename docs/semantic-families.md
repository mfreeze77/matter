# Shadow semantic question families

MAT-033 and MAT-034 add original question definitions to the existing registry,
renderer, prepared packets and executor. They do not add a provider client,
storage engine, alert writer, scheduler or delivery channel. These questions
remain **shadow-only** until separately evaluated and qualified.

`matter.semantic.families.evidence.association_questions()` returns the fixed
`same_matter / related / different / insufficient` choice plus independent topic,
matter and occurrence comparisons. Topical similarity cannot itself establish
identity, association or independent corroboration.

`claim_evidence_questions()` asks separate support, contradiction, qualification
and established-event propositions. Support and qualification can coexist. A
planned award or a model summary is not proof that an award occurred. All heads
retain the original claim/candidate pins, packet digest, question meaning,
source scope, availability cut and occurrence/provenance lineage.

`matter.semantic.families.attention.change_question(cause)` requires one explicit
cause: `new_evidence`, `corrected_association`, `changed_policy` or `timer`.
`contribution_questions()` separately asks matching recovery, contribution to the
named objective and novelty beyond applicable observed delivery. These factors
are not multiplied into an importance score. Resolved and still relevant are
separate dimensions; uncertainty alone does not create a question for a person.

`prepare_comparison(view, packet, ...)` accepts an original claim-bound prepared
packet, pinned current/prior assessments, the original condition, and explicit
host purpose/audience contexts. Optional result, delivery receipt, preferences
and responsibilities must also be exact, scoped snapshots available at the
packet's original cut. It reads the existing context definitions, versions and
host controls; it does not choose the latest context. Contexts must apply to the
assessed matter, matching the host attention boundary even when a claim's subject
is a domain value or another entity. Context creation receipts and authority dependencies join the
packet's existing dependency audit. Assessment views select propositions,
status, causes, evidence and gaps; omitted publication/manifest fields are named
explicitly. Nothing is silently truncated, and the original packet is unchanged.

All references in the resulting model-visible view are exact, available at the
cut and included in the dependency audit, including references nested in claim,
assessment and context bodies. The shared packet reader performs those checks;
control `public_targets` bookkeeping is omitted from the semantic view. Original
definitions and records remain available through their immutable pins. This
allows the comparison to use the actual receipt/access scanners and dispatcher.

A missing optional snapshot is `not_supplied`, not proof of absence. A queued
receipt remains queued; supplying it cannot advance delivered knowledge. Hosts
must still establish whether an observed delivery belongs to the same audience,
purpose and material. The existing attention/outbox services own that admission.
Protected packets require their existing access service, context and read view
at preparation and rendering; these helpers do not grant egress permission.

Use `render_questions(specifications, prepared_packet, prefix=...)` to render
the definitions, then construct a normal `Batch`. Install those same definitions
in the normal `QuestionRegistry` for `ExecutionReceiptStore`. Existing committed
budgets, controls, exact model bindings, durable attempts, cache currentness and
qualification admission continue to apply. The families need no separate runner.

A host monitoring current source meaning must declare the existing source-head
index dependency, or publish a corrected assessment when intake changes. A pin
to an immutable historical observation alone is not a subscription to future
corrections. The validation episode reuses that existing dependency mechanism to
withhold old queued advice before the capture transport can send.

`ShadowResult(batch, result, specifications=...)` checks the exact batch,
question meaning and bindings, then projects normalized diagnostics. A malformed
sibling suppresses all projected answers. It always records qualification as
unknown, consequential use as false and proposed actions as an empty list. It
cannot merge identities, close a lifecycle condition, publish an assessment or
notify anyone. A successful provider response would not change those permissions.

The [validation receipt](validation/MAT-033-034.md) distinguishes fixture
recordings, actual core-service behavior, installed checks and remaining gaps.
The copied PR18 runtime inputs are authored synthetic data used only for context
binding checks here. They are not observed JEV judgments, an integrated
StateCivics run, independent evaluation labels or evidence of alert usefulness.
