## Purpose

Implement a full offline harness with deterministic fixture responses, controlled clocks and repeatable arm outputs. This exceeds the scaffold walkthrough: it must run complete frozen episodes, report scheduled and unresolved decisions, and exercise faulty provider shapes without claiming semantic accuracy.

## In scope

- Fixture executor, clock and fault injection, episode runner
- Structured result manifests and deterministic admission replay

## Scope boundaries

- Live provider behavior or measured live usefulness
- Marking the harness complete from a documentation or single-example smoke check

## Implementation

1. Inject a fake executor keyed by request digest and explicit fixture scenario, rather than generating answers from the same policy being tested.
2. Run the two arm manifests over complete episodes and persist scheduled, successful, abstained, failed and stale result counts.
3. Provide deterministic timeout, malformed batch, partial answer, conflicting predicate, changed-source and missing-certificate fixtures.
4. Validate final lifecycle, assessment and attention expectations derived from independently specified episode outcomes.
5. Emit a machine-readable mode marker and command/result manifest that identifies all semantic-provider and live-delivery gates as not_run.

## Acceptance criteria

### AC-1

The same corpus, fixture set and configuration reproduce identical logical outputs.

**Verify:** Run twice with controlled timestamps and compare all result digests excluding execution-instance metadata.

### AC-2

Faulted and abstained scheduled decisions remain in denominators and diagnostics.

**Verify:** Inject one of each failure class and reconcile scheduled count with all terminal outcomes.

### AC-3

Offline output cannot be presented as a successful real-provider qualification.

**Verify:** Inspect the mode/gate schema and reject a report that claims provider accuracy from fixture mode.
