## Purpose

Define repeatable episode-level data partitions and arm manifests that isolate the semantic contribution. Prevent duplicates, source-derived summaries and iterative question rewrites from leaking across tuning and final evaluation, and make evidence differences visible instead of attributing them to a model.

## In scope

- Deterministic grouped partitions and arm manifests
- Frozen baseline/candidate inputs and declared ablations

## Scope boundaries

- Selecting the best threshold on the final test split
- Comparisons with unmatched evidence hidden behind aggregate metrics

## Implementation

1. Group all related observations, occurrences and derived summaries by episode/provenance before partitioning; retain the assignment seed and group keys.
2. Create distinct tuning, qualification and final evaluation partitions with a manifest that records when a reused held-out set became tuning data.
3. Define A as the deterministic policy and B as that same policy plus declared semantic families, using identical event streams and fixed packet profiles.
4. Reject incomparable arm manifests unless the changed retrieval or preparation is declared as a separate experiment with its own scope.
5. Emit leakage diagnostics, per-partition label/support counts and a reproducible paired case mapping.

## Acceptance criteria

### AC-1

No source lineage or occurrence group appears in more than one partition.

**Verify:** Run a deliberate paraphrase/copy leakage fixture and assert a blocking split diagnostic.

### AC-2

A and B resolve to exactly the same eligible cases and packet snapshots in the principal comparison.

**Verify:** Compare manifest hashes and reject a hidden candidate-only attachment.

### AC-3

Changing a tuning seed is reproducible and cannot silently replace a frozen final partition.

**Verify:** Generate twice with the same seed and require an explicit new manifest revision for a changed partition.
