## Purpose

Establish the evidence needed to release the shared Matter runtime and its first qualified integrations. The release claim must state which profiles, versions, workloads and operational boundaries were actually evaluated.

## In scope

- Integrated contract, deterministic, provider and host evidence matrix.
- Documented release scope, remaining limitations and independent replay inputs.

## Scope boundaries

- Deploying or modifying a downstream project as part of this planning ticket without that implementation task.
- Treating synthetic checks as evidence of live provider or user outcomes.

## Implementation

1. Freeze supported versions, profile set, evaluation cohorts, metrics and acceptance limits before final scoring.
2. Run the same required lifecycle cases across at least the Oil and civic contract profiles, then the declared real-provider and host evaluations.
3. Publish a release receipt separating verified guarantees, experimentally supported behavior and unqualified extensions; include reproducible inputs and rollback evidence.

## Acceptance criteria

### AC-1

Every claimed release capability maps to an executed acceptance result with exact versions and inputs.

**Verify:** Audit the release matrix against ticket completion evidence and reject unsupported capabilities.

### AC-2

Cross-profile portability preserves the core guarantees without forcing shared domain meanings.

**Verify:** Compare common conformance cases plus profile-specific authority, time and resolution cases.

### AC-3

Failure, quiet-case misses, unresolved transport outcomes and measured overhead are disclosed against preregistered limits.

**Verify:** Independently recompute report aggregates and inspect negative cases and budget-exhausted episodes.
