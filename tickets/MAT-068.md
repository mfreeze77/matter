## Purpose

Reuse IO2-142 and the existing cognition/evaluator clients to prepare bounded per-proposition Matter assessments. Bind every question and result to the actual admitted evidence, source versions, scope, coverage, sharing policy and evaluator identity; cache unchanged valid work and leave optional research detached.

## In scope

- Claim-specific code/docs/skills/tests/config evidence domains
- NarrowState/JudgmentEvidenceSource and final-payload adaptation
- Packet hashes, citation ownership, read dependencies, coverage and availability cuts
- Existing evaluator/provider client reuse and deterministic recorded-result mode
- Targeted semantic cache invalidation and bounded optional investigation handoff

## Scope boundaries

- A new repository evidence graph or unrestricted model browsing
- Automatic trust promotion or model-written scope/intent
- Assuming unavailable evidence is a negative finding
- Real provider evaluation or production integration in this scaffold
- Making model availability mandatory for deterministic matter maintenance

## Implementation

1. Define the Oil assessment adapter over MAT-027/028 question and packet contracts. Each request names one proposition or explicit comparison, claim kind, applicable rule/profile, source and audience/purpose versions, availability cut, completeness/omissions and admitted content digest.
2. Translate IO2-142 domain preparation and NarrowState/JudgmentEvidenceSource results without expanding the final admitted scope. Reuse named ticket paths, repository profiles and existing EXAIS/cognition clients; preserve pathless/refused-owner conservative behavior and provider sharing restrictions.
3. Map actual final request/citation bytes into evidence receipts, including source snapshot identity, excerpt ranges, per-claim ownership and absence coverage. Register content dependencies and complete-scope absence watches in the operational namespace so later relevant evidence invalidates the result.
4. Invoke the existing evaluator clients through the Matter question/provider seam with pinned contract/model settings and bounded batches. Validate that results bind the exact packet, claim and admitted citations; return named unavailable/contract-mismatch/unknown states instead of retrying unboundedly.
5. Cache results by semantic packet and evaluator/rule identity. Reuse unchanged valid judgments across renderings and timer ticks; source, coverage, rule or relevant purpose changes invalidate only affected work. Do not mix actor intent, prior generated advice or unrelated working beliefs into a narrow evidence question.
6. Provide an optional bounded investigation request through the existing coordinator/session seam when a named missing fact could alter a decision. Bind allowed paths/scope, read/call/byte/deadline budgets and stopping conditions; persistence and deterministic lifecycle must succeed with this facility disabled.

## Acceptance criteria

### AC-1

Each assessment is bound to the exact admitted claim-specific payload and cannot cite refused, future or unadmitted evidence.

**Verify:** Use citation-present, citation-missing, code-contradiction, pathless-owner, refused-owner and future-available fixtures; independently mutate final payload/citation ownership and verify named refusal or incomplete outcome.

### AC-2

Unchanged semantic packets reuse valid judgments, while changed relevant source or absence coverage invalidates dependent assessments and pending attention.

**Verify:** Replay identical packets under timer/render/session changes, then modify a cited file and add previously absent in-scope evidence; assert unchanged cases make zero extra evaluator calls and changed cases invalidate the appropriate dependency chain.

### AC-3

Every evaluator/investigation path stays within declared sharing, byte, call and elapsed-time budgets and fails without blocking ordinary host work.

**Verify:** Run deterministic fake-provider oversize/refusal/timeout/cancellation scenarios and local-only evidence cases; inspect request receipts, budget accounting and hook latency without requiring a paid provider.

### AC-4

The adapter works in a provider-disabled profile and does not convert interpretation into accepted authority.

**Verify:** Run deterministic failure/recovery episodes with all provider clients unavailable; assert lifecycle and quiet/eligible decisions still operate, semantic status remains explicit unknown, and ledger authority/projection is unchanged.

- Provider-disabled deterministic capture/recovery and bounded investigation timeout

## Risks

- Reusing a prepared context before its final filtering/byte cut can falsely advertise evidence that the evaluator never saw.
- Missing coverage dependencies allow an apparently negative judgment to remain current after relevant evidence arrives.
- Wrapping providers twice can duplicate cost, receipt ownership and retries unless the existing client remains the invocation owner.
- Model confidence and diagnostic margins are not calibrated authority or a universal matter priority.
