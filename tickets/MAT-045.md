## Purpose

Assemble the evidence required to decide which semantic families may leave shadow mode. The release record must identify exact code, data, model and policy versions, distinguish executed from unrun gates, and keep failed or inapplicable families disabled without discarding their diagnostic results.

## In scope

- Release manifests, per-family gate matrix and reproducibility checks
- Qualification scope, outstanding failures and revocation conditions

## Scope boundaries

- Automatic production deployment or host permission changes
- Marking roadmap tickets complete because documentation exists

## Implementation

1. Collect commit and dependency versions, corpus/split hashes, label provenance, exact question/renderer/packet identities and model-resolution evidence.
2. Attach executed commands, logs, raw-response references, calibration records, sensitivity results, paired outcomes, silence audits, interleaving checks and overhead reports.
3. Produce a gate matrix using passed, failed and not_run with evidence locators and scope for every required gate; missing evidence remains unrun.
4. Compute the eligible family set from applicable passing certificates and deny activation when a required family or host compatibility gate is missing.
5. Provide a reproducibility command plan and explicit conditions that revoke or require requalification, while keeping private artifacts out of the repository.

## Acceptance criteria

### AC-1

A release with only fixture evidence cannot claim a qualified live provider or observed delivery benefit.

**Verify:** Attempt to assemble that release and verify provider/usefulness gates remain not_run.

### AC-2

Every passing gate resolves to an executed command and immutable evidence identity.

**Verify:** Run manifest consistency checks and reject missing artifacts, altered hashes or mismatched model versions.

### AC-3

Only passing applicable families enter the eligible set and a later revocation removes them.

**Verify:** Combine one passing, one failed and one stale certificate, then inspect eligibility before and after revocation.
