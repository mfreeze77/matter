## Purpose

Assemble rule families into separate evidence, lifecycle, purpose, and audience components. Domain meaning belongs in profiles, not application-name branches or one universal score.

## In scope

- Profile registry and immutable revisions
- Semantic fingerprints and compatibility
- Required-output, capability, and budget validation

## Scope boundaries

- Live policy editor
- Automatic qualification transfer

## Implementation

1. Define profile components with immutable rule references and multiple assessments per matter.
2. Validate required paths, outcome implications, conflict resolvers, permissions, and budget feasibility.
3. Fingerprint labels, definitions, ordering, rendering, and preparation where they affect meaning.
4. Emit profile supersession changes without rewriting historical assessments.

## Acceptance criteria

### AC-1

Changing meaning with unchanged output shape changes the semantic binding.

**Verify:** Compare same-topic and same-matter Choice profiles.

### AC-2

Impossible or unauthorized profiles fail with a concrete path.

**Verify:** Test missing rule, undefined label, denied capability, and impossible call budget.

### AC-3

Audience cadence changes leave evidence fingerprints unchanged when independent.

**Verify:** Compare component fingerprints and dependency sets.
