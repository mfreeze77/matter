## Purpose

Create the execution boundary shared by fixture, recorded, and optional remote providers. Keep transport results, primitive validation, qualification, and host authority as separate objects so a successful response cannot directly mutate a matter or send advice.

## In scope

- Serializable question, batch, typed-answer, fault, and admission contracts
- Adapter capability declaration and injected fixture interface

## Scope boundaries

- Vendor client construction in the core
- Domain policy, speaker assignment, or delivery implementation

## Implementation

1. Define explicit Choice, rubric Score, and proposition-probability variants with preserved raw representations and required fields.
2. Specify exact answer-ID matching, unsupported primitive handling, whole-batch admission, and retained per-answer diagnostic outcomes.
3. Define an executor protocol that accepts immutable batches and deadlines, returning execution metadata without obtaining credentials itself.
4. Add capability negotiation that rejects unsupported types before dispatch and expose an importable offline implementation seam.
5. Document that evaluation returns evidence for subsequent host checks and cannot accept intent or call host actions.
6. Define lossless decimal normalization for probability, fractional Score, confidence, and residual fields: preserve original wire bytes/lexemes, use the core's declared decimal strings, and prohibit silent binary-float conversion before validation or digesting.

## Acceptance criteria

### AC-1

Core contracts import and serialize without any installed provider SDK or credentials.

**Verify:** Run the import and round-trip conformance suite in an environment with provider extras absent.

### AC-2

Each primitive retains its distinct semantics and missing/extra answer IDs fail batch admission.

**Verify:** Exercise one valid shape and missing, duplicated, unexpected, and wrong-type responses per primitive.

### AC-3

A returned answer cannot directly call a host mutation or delivery hook.

**Verify:** Use a spy host in a protocol test and assert no action callback occurs during evaluation.

### AC-4

Primitive round-trip preserves exact provider numeric values in canonical core decimal fields without binary-float rounding.

**Verify:** Round-trip a raw high-precision Noul value (0.1234567890123456789) plus fractional Score, probabilities, confidence, and residual fixtures; compare original bytes, normalized decimal strings, and canonical digest after re-encoding.

## Required test cases

- Noul 0.5 stays a proposition probability, not an importance level.
- A fractional Score keeps its rubric and distribution.
- An unknown provider type fails before dispatch.
- Lossless numeric round-trip keeps raw provider lexemes separate from canonical decimal strings; a binary-float-only fixture cannot claim exact numeric admission.

## Risks

- A universal float interface would erase meaning.
- Import-time SDK initialization could cause unintended network or credential access.
