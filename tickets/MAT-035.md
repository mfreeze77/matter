## Purpose

Extend fixed-packet assessment with narrowly controlled evidence requests once the basic judgment families are qualified. An investigation must pursue a named uncertainty using host-approved candidate reads and retain why it stopped; it cannot become an autonomous retrieval loop that hides cost or manufactures sufficiency.

## In scope

- Gap-specific candidate evaluation and bounded follow-up packets
- Stopping receipts, repeated-request suppression and remaining conflicts

## Scope boundaries

- Unrestricted browsing or source discovery
- Automatic consequential actions after retrieval

## Implementation

1. Represent the missing claim requirement, eligible source roles, candidate reads, expected information gain and remaining budget in the investigation request.
2. Use qualified relevance/gap judgments only to rank the permitted candidates; deterministic host controls select and execute the read.
3. Record each returned observation and prepare a new packet through the same provenance and availability rules.
4. Implement explicit stops for sufficient evidence, no eligible source, conflict, exhausted budget, stale purpose and a genuinely authorized decision.
5. Detect repeated equivalent read requests and require a changed gap or evidence revision before another cycle; preserve counterevidence requirements throughout.

## Acceptance criteria

### AC-1

Budget exhaustion and unavailable sources never produce a resolved or evidence-sufficient result.

**Verify:** Run exhausted-round and denied-source fixtures and inspect distinct terminal reasons.

### AC-2

A candidate outside the host-provided source set cannot be fetched regardless of model ranking.

**Verify:** Inject an out-of-set candidate ID and assert validation failure with no read call.

### AC-3

Repeated requests for the same unchanged gap stop without losing its unresolved status.

**Verify:** Replay an unhelpful retrieval loop and inspect suppression count, budgets and preserved gap.
