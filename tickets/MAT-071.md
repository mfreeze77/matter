## Purpose

Run a downstream comparative qualification of the Matter candidate against the corrected current Oil baseline using frozen chronological cohorts, native fault scenarios and authorized live owner sessions. Report retained catches and misses alongside noise, timing, overhead and actual outcome stages; require zero ordinary closeout without treating source-reported historical tests as candidate evidence.

## In scope

- Baseline/candidate/corpus/profile/model/config pins and separate evidence classes
- Chronological as-of replay, quiet-decision sampling and held-out human outcomes
- Native concurrency, crash, task/compaction and dispatch-freshness scenarios
- Matched baseline/candidate or preregistered threshold arms on frozen cohorts
- Provider re-execution and live session evidence as distinct authorized runs
- Retained catches, missed/delayed developments, interruption/cost and zero-closeout release gates

## Scope boundaries

- Claiming historical October-7 tests were run by this scaffold
- Treating installed replay as witnessed owner consumption
- Using a quieter output count alone as proof of improvement
- Tuning on held-out human outcomes or claiming replay removes parametric future knowledge
- Launching live/provider workloads or enrolling/deploying a host from this ticket draft

## Implementation

1. Freeze baseline Oil at the reviewed corrected commit and candidate implementation bytes, plus Matter/profile/adapter schemas, evaluation bindings, resource/attention settings and dataset manifests. Record old incidents as scenario provenance rather than presuming every old annoyance remains in the corrected baseline.
2. Assemble episode cohorts with successful/no-output recovery, real repeated failure, task/workdir collisions, source invalidation, explicit control changes, compaction, unavailable evidence, real decisive catches and deliberately quiet cases. Bind event/effective/available/observed timestamps and include incomplete capture labels.
3. Separate development/tuning cohorts from held-out human outcomes and, where relevant, later temporal cohorts. Preregister threshold/attention-policy arms on the same frozen inputs and define catch/miss/latency/noise/resource gates before reviewing held-out outcomes.
4. Run deterministic chronological replay with frozen recorded/fake evaluator outputs and bounded jobs. Report incomplete runs and timing_mode=stepwise_structural honestly; add dedicated native worker/mailbox race, restart and host-output fault scenarios for timing/concurrency acceptance.
5. Run separately authorized provider re-execution only with pinned payloads, model/settings and sharing constraints, distinguishing recorded-output reproducibility from fresh provider quality. Document that as-of input gating does not establish provider ignorance of future information.
6. Run authorized live owner-session comparison through existing host enrollment/configuration. Collect transport milestones, optional actual consumption, action correspondence and independently judged usefulness without prompting for routine acknowledgement or Oil closeout.
7. Produce per-episode and aggregate retained catches, missed/delayed material developments, sampled quiet errors, duplicate/nonactionable hints, interruption episodes/characters, event-to-ready/emission distributions, hook/worker latency, calls/bytes/spend, queue/storage growth and cold/warm/restart costs.
8. Apply the preregistered release gates and report every failure/unknown with exact evidence class. Fewer hints cannot pass while unacceptable misses, stale output, lost controls, unbounded cost or required ordinary closeout remain. Keep the roadmap completion state not_run until real receipts exist.

## Acceptance criteria

### AC-1

The report binds exact baseline/candidate/corpus/profile/evaluator versions and keeps deterministic replay, provider runs, installed native witnesses and actual live sessions distinct.

**Verify:** Validate manifests and per-run evidence labels; reproduce deterministic decisions from the retained frozen corpus and reject a report that substitutes the October-7 source-reported suite for candidate execution.

### AC-2

Noise reduction is assessed together with retained catches, missed/delayed material developments and sampled quiet decisions against held-out human outcomes.

**Verify:** Run the same preregistered arms on frozen cohorts; review held-out labels after tuning closes and calculate each registered metric/gate with episode denominators and uncertainty or explicit insufficient-sample status.

### AC-3

Native freshness, control, concurrency and crash behavior meets the declared host cutoff and budget contracts rather than being inferred from chronological replay.

**Verify:** Execute MAT-070 race/fault scenarios on the pinned candidate, retain exact native output/receipt timelines and compare hook/control/resource distributions to preregistered budgets.

### AC-4

The release evidence shows zero required ordinary closeout actions and makes no unsupported claim of consumption, causal usefulness or future-leakage elimination.

**Verify:** Audit required user actions and staged receipts in the live/native cohort; require zero new routine closeout prompts, mark absent consumption as unknown and verify replay reports preserve parametric/timing limitations.

## Risks

- A small or selected session sample can look quieter while missing important developments; report sample scope and uncertainty.
- Historical corrected behavior and current provider availability may differ from old incident traces.
- Structural replay cannot establish real host races or eliminate a provider's prior knowledge of future facts.
- Automatic feedback prompts can create the very interaction cost being measured; use optional existing feedback and held-out evaluation instead.
- Noise/cost tuning after reading held-out outcomes invalidates the comparison and requires a fresh cohort.
