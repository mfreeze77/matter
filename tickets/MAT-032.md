## Purpose

Add one optional provider path that satisfies the same neutral contracts as offline fixtures. Inspect and choose the existing OIL arbitrary-question transport or the documented TypeSafe SDK boundary, then qualify the exact chosen adapter instead of adding competing transport implementations.

## In scope

- Optional dependency/transport decision, typed normalization and instrumentation
- Explicit provider selection, retry limits, deadlines and model resolution

## Scope boundaries

- Provider calls in default tests
- New provider subscriptions or production deployment

## Implementation

1. Record an adapter decision comparing OIL ask(state, questions) with a pinned SDK surface, including dependencies, licensing and error behavior.
2. Project canonical specifications into actual Choice, ordered Score and Noul request shapes without losing criteria or field references.
3. Normalize HTTP and selected SDK representations through the strict validator, preserving raw answers and trusted precision assumptions.
4. Add explicit model, credential, timeout and retry configuration; count each attempted call against the host budget and redact secrets from faults.
5. Capture requested/resolved model, response usage and observable bytes; a missing model or selected adapter is an explicit error, not a synthetic fallback.
6. Capture raw HTTP numeric lexemes before SDK normalization; parse and validate with exact decimal arithmetic, emit canonical core decimal strings, and record precision unavailability when an SDK exposes only rounded binary floats without recoverable wire evidence.

## Acceptance criteria

### AC-1

No provider dependency or network access is needed for core imports and default tests.

**Verify:** Run the suite with provider extra absent and a network-denying test transport.

### AC-2

The selected adapter preserves all three native shapes and rejects malformed responses.

**Verify:** Feed documented HTTP and SDK-shaped fixtures, including integer Score indices, through one conformance suite.

### AC-3

Timeouts, rate limits and model-resolution failures consume recorded attempts and remain unqualified.

**Verify:** Use injected transport failures to inspect retry limits, receipts and admission status.

### AC-4

The transport bridge preserves wire numeric precision through validation, normalization, and receipt hashing.

**Verify:** Feed raw HTTP high-precision Noul and fractional Score/distribution/confidence fixtures through the adapter and back through the core encoder; compare bytes, exact decimals, residuals, and digests. Exercise a binary-float-only SDK response and require explicit unqualified precision status rather than silent rounding.

- Noul has no invented vendor confidence.
- A response cannot choose a wider precision tolerance.
- A keyless explicitly selected provider run reports missing configuration.

## Risks

- SDK/HTTP shape differences can silently alter Score indexing.
- Two independent transports can drift unless they share conformance tests.
