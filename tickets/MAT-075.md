## Purpose

Provide a small callable inspection surface for matters, evidence, assessments and attention explanations. Applications should be able to embed the library or adapt a transport without requiring a new service deployment.

## In scope

- Read-only queries, pagination, current/as-of views and explanations.
- A documented client contract and CLI suitable for operator investigation.

## Scope boundaries

- Deploying or modifying a downstream project as part of this planning ticket without that implementation task.
- Treating synthetic checks as evidence of live provider or user outcomes.

## Implementation

1. Specify the core operations and error/coverage responses before selecting optional transport bindings.
2. Build bounded read projections for current state, historical knowledge, evidence paths and attention reasons.
3. Add CLI output that uses public schemas and can be consumed without exposing internal storage or provider details.

## Acceptance criteria

### AC-1

The same matter can be inspected for different purposes/audiences without rewriting shared identity.

**Verify:** Run paired queries with divergent delivery profiles and compare identity, evidence and assessment bindings.

### AC-2

Why-open, why-changed, why-quiet and why-delivered queries identify the governing evidence and rules.

**Verify:** Use trace fixtures with correction, delay, exhaustion and recovery and verify each explanation against recorded receipts.

### AC-3

Large histories are bounded and explicitly paginated or summarized with coverage disclosure.

**Verify:** Query a long history with small limits and verify deterministic continuation without missing or duplicated records.
