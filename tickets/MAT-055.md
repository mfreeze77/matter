## Purpose

Learn descriptive procedural and interaction regularities for a jurisdiction/body/meeting type while preserving source/profile versions, applicability, uncertain support and temporal regimes. These fingerprints guide experiments; they do not establish authority or verified identity.

## In scope

- Recognition/motion/vote/agenda style summaries
- Body/type/time-specific profile versions
- Inherited profile and jurisdiction override references
- Training support/coverage/drift metadata

## Scope boundaries

- Universal institution-to-person fingerprints
- Replacing reviewed crawler rules with learned regularities
- Training on the held-out meeting or future role changes

## Implementation

1. Define fingerprint manifests with jurisdiction/body/meeting-type, source profile digest, cohort/provenance groups, cutoff, feature/extractor versions and supporting spans.
2. Aggregate anonymous procedural patterns across eligible meetings with group-balanced support, keeping per-feature coverage and variability instead of a single certainty score.
3. Compare a generic meeting profile, a sourced local-rule profile, and an empirically learned profile on the same frozen cohort; preserve unknown profiles as a valid condition.
4. Detect chair/rule/meeting-mode regime changes; propose a new profile version with effective and availability times instead of rewriting historical profile behavior.
5. Export descriptive profile references and qualified applicability only, leaving legal capability and person assignment to their separate owners.

## Acceptance criteria

### AC-1

A fingerprint cannot contain test-meeting/future evidence or silently cross body/jurisdiction scope.

**Verify:** Run train/test/source-group contamination sentinels and validate rejected profile manifests.

### AC-2

Changing the chair or meeting type creates a separately applicable regime instead of retroactively changing old assessments.

**Verify:** Replay profile versions over chronological meetings with an explicit transition source.

### AC-3

Learned regularities and reviewed procedural rules remain distinct in packets and reports.

**Verify:** Inspect profile fields, provider-visible state and assessment explanations in a paired comparison.

### AC-4

A no-profile or unsupported-profile case is reported and remains evaluable.

**Verify:** Run missing/ambiguous institution controls without dropping their query segments.
