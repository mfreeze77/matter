## Purpose

Create controlled probes that expose whether a semantic family follows its declared meaning and how much ordinary call variation affects the comparison. Separate intended invariance from deliberate meaning changes, and report failures without treating cross-question agreement as ground-truth correctness.

## In scope

- Repeated calls, option-order remapping and label/definition controls
- Changed-question pairs and logical-coherence diagnostics

## Scope boundaries

- Assuming hosted-model internal architecture
- Applying another model paper’s failure rate to Matter

## Implementation

1. Prepare repeated identical requests to estimate within-snapshot variation before comparing altered renderings.
2. Generate option-order permutations, neutral-label substitutions and meaningful-name-to-definition swaps with explicit semantic remapping to original outcomes.
3. Add paired topic/matter/occurrence questions on examples whose correct answers differ, so a model repeating an old answer fails meaning sensitivity.
4. Run complementary and equivalent propositions in separate and bundled requests; preserve contradictions and do not multiply their probabilities.
5. Produce a probe manifest and per-family qualification impact report including raw receipts, independent labels and affected specification revisions.

## Acceptance criteria

### AC-1

Order and label probes compare mapped semantic outcomes rather than raw option strings.

**Verify:** Use deliberately permuted fixture labels and verify the remapping against a known oracle.

### AC-2

Changed-question tests detect an evaluator that always returns the original answer.

**Verify:** Use paired same-topic/different-matter and same-matter/new-occurrence cases with fixed expected differences.

### AC-3

Observed inconsistency is reported relative to repeat variation and cannot become a joint probability.

**Verify:** Inspect complement/bundling output and test the composition boundary rejects unsupported probability products.
