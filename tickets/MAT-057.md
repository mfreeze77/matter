## Purpose

Reuse existing opening/closing lexical features and test whether syntax, repairs, hedges and phrase structure add useful context beyond scripts and topics. All grammar features are proposed research with explicit parser/ASR uncertainty, not existing identity capabilities.

## In scope

- Existing lexical boundary-feature adapter
- Experimental grammar/repair/formula feature families
- Script/topic/name-masking controls
- Versioned feature definitions and availability

## Scope boundaries

- Rebuilding existing behavior n-grams under a second service
- Using self-introductions or roster names in an acoustics-only result
- Treating lexical similarity as calibrated identity probability

## Implementation

1. Wrap the existing lexical-timing-v1 output in the experimental feature manifest; retain original definitions and avoid changing B-arm semantics.
2. Define a bounded grammar candidate inventory with units and source spans: clause/repair/hedge structures, question formation and formulaic openings/closings; select any parser only after dependency/license/reproducibility review.
3. Tag shared institutional scripts and explicit names/quoted speech through separate field views, with source quality and parser version; unavailable/ambiguous grammar stays unknown.
4. Compare original lexical support, masked/formula-controlled variants and added grammar over identical queries/reference groups; include topic-swapped and script-shared controls.
5. Preserve exact evidence shown to a semantic evaluator and outcome qualification per question family; export descriptive features only to the experimental decision layer.

## Acceptance criteria

### AC-1

Existing prefix/suffix features retain their original version/meaning and are not counted as a new implemented grammar capability.

**Verify:** Compare wrapper output to existing behavior test fixtures and inspect version fields.

### AC-2

Shared scripts and self-introduction names cannot leak into a claimed acoustic-only or name-masked condition.

**Verify:** Run sentinel/script controls and verify packet bytes plus separate labeling of explicit-name evidence conditions.

### AC-3

Missing or low-quality ASR/parser output is reported rather than converted into confident grammar features.

**Verify:** Use truncated turns, uncertain tokens and malformed parser responses; inspect availability/failure reasons.

### AC-4

Any claimed grammar gain is measured against lexical-only and script/topic controls on the same cohort.

**Verify:** Publish paired per-meeting results and errors with frozen feature/config digests.

- Script and role effects can masquerade as personal patterns.
