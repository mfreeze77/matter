## Purpose

Connect Matter attention to Oil's existing native host and mailbox flow with source/control freshness at a documented observed dispatch cutoff. Preserve parent/task routing, compaction behavior, decisive-only bounded delivery and staged receipts, without adding a second transport queue or mandatory approval/closeout loop.

## In scope

- Attention-to-Finding/mailbox adapter and one transport owner
- Audience/purpose/assessment/source/control/delivered-baseline validation
- Native direct-control handling, parent/subagent routing and compaction semantics
- Lease/fencing, attention budget reservation, cancellation and unknown outcome policy
- Observed transport receipts distinct from consumption/action/usefulness

## Scope boundaries

- Sending Slack/email or other external messages without host authorization
- Claiming exactly-once delivery or reading from local output-flush confirmation
- New mandatory acknowledgements, human approvals, synchronous model gates or closeout
- Replacing standing-context retrieval or resetting matter state at compaction
- Unbounded precommit hold or changing accepted host permission decisions

## Implementation

1. Map neutral attention/outbox intent to the existing mailbox and native Finding contract, keeping the mailbox as the single transport queue. Bind matter/assessment revision, evidence manifest digest, audience/purpose, control epoch, prior delivered baseline and stable delivery key; persist references through the owner adapter.
2. Integrate a bounded local freshness callback at the native delivery boundary. Revalidate source versions, assessment validity, recovery, dispositions, audience/task purpose, cancellation and delivered baseline before the declared irreversible-output cutoff; document which observations are included and how concurrent updates fence a lease.
3. Use existing reserve/confirm behavior and exact rendered IDs. Advance the delivered baseline only at the host's declared successful transport milestone, record late invalidation races, and keep a durable delivery_unknown outcome for ambiguous crash/timeout windows with a capability-aware bounded retry policy.
4. Preserve configured decisive-only model filtering and per-boundary item/character limits; keep standing-context and cognition budgets distinct. Atomically reserve attention capacity so concurrent workers cannot consume the same remaining allowance, without turning resource-budget failure into an assertion that nothing matters.
5. Route subagent evidence to parent audiences while retaining child task provenance and capability scope. On task changes or SessionStart/compaction, reset only the appropriate presentation epoch; retain matter identity, resolution, accepted controls, protected associations and prior receipts.
6. Keep authenticated controls and actual host permission boundaries on their native immediate path. Existing precommit advisories remain bounded/fail-open; the adapter must not introduce an extra human decision or mandatory semantic work for normal tool use.
7. Expose precise why_quiet/why_delivered/what_changed and staged outcome receipts. Local emitted output records host acknowledgement unknown unless a separate native receipt exists; later success is linked at its supported correspondence strength without claiming advice caused it.

## Acceptance criteria

### AC-1

Recovery, cancellation or a dependency change observed before the host's declared dispatch cutoff prevents stale output; events after irreversible output are recorded honestly.

**Verify:** Inject each event before reservation, after lease, immediately before cutoff and after flush; assert withheld/cancelled or actual-emission-plus-race receipts at the documented linearization point without claiming retroactive prevention.

### AC-2

Mailbox leases and crash recovery do not fabricate delivery/consumption or blindly claim duplicate-free delivery when the outcome is unknown.

**Verify:** Fault around render, output write, flush and confirm; verify exact rendered IDs, delivered baseline advancement only on the declared milestone, delivery_unknown retention and the declared bounded retry/idempotency policy.

### AC-3

Parent/child task boundaries and compaction remain correct while resolved matters and accepted controls survive presentation resets.

**Verify:** Run a parent with two children, task switch and compaction sequence; assert no child-directed unauthorized hint, no cross-task content leakage and no reopened resolved matter or erased disposition.

### AC-4

The candidate preserves native decisive-only caps and direct-control responsiveness and requires zero new ordinary closeout or approval actions.

**Verify:** Exercise over-cap findings, unsettled model results, provider outage, concurrent leases and precommit cancellation using native host fixtures; compare output/latency gates to the frozen baseline and count required user closeout actions as zero.

## Required test cases

- Recovery/source edit/cancel arriving before and after native irreversible output
- Crash after render, partial write, flush and confirm; unknown delivery versus actual receipt
- Concurrent workers competing for one audience budget and delivered baseline
- Decisive versus unsettled items under existing three-item/1,800-character default boundary
- Two subagents with same command/path but distinct task identity and parent audience
- Compaction reintroduces applicable standing context without reopening resolved matters
- Direct stop/permission denial with provider unavailable or matter worker backlogged
- Native precommit advisory timeout remains bounded and fail-open

## Risks

- Mailbox acceptance or local flush can be mistaken for reading/usefulness; staged receipts are required to prevent that false claim.
- A freshness check performed only when preparing a Finding leaves a stale interval before actual emission.
- A second outbox implementation can duplicate delivery and compete with the existing mailbox owner.
- Compaction resets presentation memory today; treating that as a domain reset would reopen old noise.
