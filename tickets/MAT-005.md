## Purpose

Create the durable continuing-subject aggregate for questions, opportunities, and problems. Keep domain extensions optional and identity independent from title, lifecycle projection, and contextual importance.

## In scope

- Stable matter creation and scoped key lookup
- Revisioned descriptions and extensions
- Cross-run identity conflicts

## Scope boundaries

- Global semantic clustering
- Merges and domain transitions

## Implementation

1. Implement opaque persistent matter IDs and adapter-owned identifier namespaces.
2. Resolve exact keys within scope while returning ambiguous mappings as conflicts.
3. Revision description changes without replacing identity or history.
4. Allow unassociated evidence and multiple assessments without requiring user-created tickets.

## Acceptance criteria

### AC-1

One declared subject key resolves after run and process changes.

**Verify:** Restart storage and ingest later evidence with a new processing-run ID.

### AC-2

Changing title, purpose, or audience preserves matter identity.

**Verify:** Update display metadata and bind several contexts.

### AC-3

Scope collisions and ambiguous keys return explicit outcomes.

**Verify:** Test duplicate keys across scopes and conflicting mappings within one scope.
