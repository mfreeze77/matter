## Purpose

Build one canonical registry of semantic question definitions and render exact provider-neutral instances. A stable ID must never conceal changed wording, option meaning, rubric order, or field bindings, because those changes invalidate the evidence behind qualification.

## In scope

- Versioned specifications, render manifests, ordered criteria digests
- Static outcome sets and explicit field-path bindings

## Scope boundaries

- An unrestricted prompt generator
- Automatic qualification of rewritten questions

## Implementation

1. Store the family, revision, complete instructions, primitive, ordered criteria, required fields, and renderer version as immutable specification data.
2. Render instructions with explicit packet paths and persist the exact materialized question plus correlation ID; reject missing required bindings.
3. Hash a canonical representation that preserves array and criteria presentation order while distinguishing specification identity from concrete input identity.
4. Provide fixed association outcomes and self-contained Score descriptions; reserve dynamic candidate options for an explicitly evaluated extension.
5. Produce a semantic-diff report identifying the field that changed and the certificates requiring applicability review.

## Acceptance criteria

### AC-1

An opaque question ID does not change the complete instructions supplied to the evaluator.

**Verify:** Render equivalent definitions with two IDs and compare model-visible instructions and semantic digests.

### AC-2

Changing a rubric, option description, order, or renderer changes the appropriate identity.

**Verify:** Run mutation cases for every fingerprinted field and inspect invalidation reasons.

### AC-3

Missing state bindings cannot render as empty text or a guessed question.

**Verify:** Attempt a absent candidate path and assert a named rendering failure before dispatch.
