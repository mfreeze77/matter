## Purpose

Persist sufficient execution evidence to inspect an assessment and replay admission decisions without reissuing a provider call. Reuse must distinguish the original observation from retries and cache hits, while qualification and current-state eligibility remain separately invalidatable.

## In scope

- Immutable receipt storage, response artifact references, exact cache keys
- Attempt lineage, usage, timing and unavailable-measurement reasons

## Scope boundaries

- Storing credentials or private provider responses in version control
- Treating cache replay as an independent model trial

## Implementation

1. Bind source packet, rendered question/order, model request/resolution, adapter/precision version and stage parents into the receipt identity.
2. Store raw response references and validation faults alongside normalized answers; retain partial diagnostic heads without making a failed set admissible.
3. Record dispatch, completion, timeout, retry and cancellation events with logical request and attempt IDs.
4. Implement exact reuse over the semantic request and execution assumptions, then rerun current qualification and freshness checks on every reuse.
5. Represent missing token usage, unknown wire bytes or unavailable pricing as null with reasons and exclude secrets from persisted fields.
6. Store original response bytes separately from normalized decimal-string probability/Score/confidence/residual fields; bind numeric representation and trusted precision to the receipt and reuse key, never reconstructing exact evidence from rounded binary floats.

## Acceptance criteria

### AC-1

A cache hit preserves the original receipt and records reuse without new corroboration.

**Verify:** Run the same frozen request twice and inspect attempt, cache and occurrence counters.

### AC-2

Model, criteria order, renderer, packet or precision changes prevent incompatible reuse.

**Verify:** Mutate each field independently and assert the original cache entry is ineligible.

### AC-3

Failed batches remain inspectable and cannot become admissible through replay.

**Verify:** Replay a response with one invalid head and verify retained diagnostics plus rejected admission.

### AC-4

Persisted and replayed receipts retain original numeric wire evidence and stable canonical decimal values.

**Verify:** Persist, reload, and replay high-precision Noul and fractional Score/distribution receipts; verify unchanged raw bytes, exact decimal fields, trusted residual, and normalized digest. A rounded binary-float reconstruction must not match as exact reuse.

## Required test cases

- Revoking a certificate invalidates a previously cached high-confidence result.
- Absent SDK byte counts remain null.
- Retrying one provider call creates attempts, not source evidence.
- Receipt storage/replay round-trip preserves 0.1234567890123456789 and fractional Score distributions without binary-float loss; changing a precision profile invalidates exact reuse.

## Risks

- Overbroad cache keys can silently reuse another question.
- Discarding partial faults produces survivorship bias in evaluation.
