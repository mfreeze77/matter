## Purpose

Provide a neutral PostgreSQL implementation of Storage and shared conformance for host-backed PayloadStore implementations so StateCivics can keep Matter's ledger and payload recovery in its existing database infrastructure. Decision 0003 makes both ports prerequisites for StateCivics production activation: no interim production mount or temporary deployment/file-backup plumbing. Retain SQLite and the existing rehearsal for comparison and verification. StateCivics owns its packet/response adapter, receiving integration and activation; this ticket owns the Matter SDK work only.

## In scope

- A synchronous PostgreSQL Storage implementation opened through a host-supplied psycopg connection factory or pool lease, with explicit transaction ownership, connection cleanup and scope isolation.
- Equivalent canonical history, command idempotency, revision checks, consistent snapshots, historical proof reads, guarded retries, dependency watches, transaction hooks and uncertain-outcome handling.
- Database coordination that protects absent records and competing discoveries, plus an explicit host contract preserving per-place and per-lens review exclusion across separate commands.
- Reusable PayloadStore conformance and a synthetic host adapter fixture covering durable exact-byte put/read, packet reconstruction, raw response artifacts and availability/access boundaries.
- Versioned PostgreSQL migrations, integrity verification, actual restore checks, SDK compatibility guidance and installed-package evidence, reusing the existing SQLite behavioral scenarios.

## Scope boundaries

- Interim production data/matter mounts, MATTER_STORE_ROOT directory rollout, temporary file-backup/deployment plumbing or activating SQLite first.
- Editing or deploying StateCivics, Oil, the crawler or DIAT; StateCivics KS-1158 owns its host payload tables/adapter, schema/place layout, backend/worker coordination and associated storage recovery/receiving acceptance. Encryption remains KS-637/KS-1152 work; the production dispatcher (KS-1127) and activation remain separate StateCivics/owner work.

- Generic retention/archival expansion under MAT-073, removal of SQLite, copying real rehearsal data into this repository, or presuming a live production SQLite migration is needed.

## Acceptance criteria

### AC-1

A host-supplied synchronous connection factory or pool lease supports the existing Storage API with explicit transaction ownership, scope isolation and durable successful returns; SQLite-only consumers remain usable.

**Verify:** Run installed-package cases with and without the optional PostgreSQL dependency, independent scopes and reused pool leases; reject unsupported/nested transaction usage and verify cleanup after both success and failure without changing unrelated host transactions.

### AC-2

Canonical versions, heads, watches, command/result bytes and receipts commit atomically; exact retries return the original result, changed content conflicts, and immutable identity/history remains intact.

**Verify:** Run the existing transaction, boundary and identity scenarios against SQLite and real PostgreSQL; compare canonical bytes/digests and public outcomes across restart, changed retries, type collisions, stale writes and corrupted stored data.

### AC-3

Competing writers cannot both win incompatible existing or absent-record decisions; watch registration and discovery races are protected, and host coordination preserves one active review per logical lens.

**Verify:** Use independent PostgreSQL connections/processes for missing-identity creation, expected-revision and negative-watch races, plus synthetic backend/worker claim races across lens revisions and matters. Assert one eligible winner, honest conflicts, bounded lock failures and safe release; a row-lock-only case must not pass by avoiding the absent-record race.

### AC-4

Snapshots are consistent and historical proof reads retain their current-head fence; replay of a durable result cannot bypass present access, revocation or scope checks.

**Verify:** Race a writer against a multi-read snapshot; test historical pins with a changed current head, foreign scopes, revoked read/egress grants and exact retry disclosure through GuardedStorage. Assert explicit refusal without rewriting the historical command or result.

### AC-5

Transaction observers and post-commit effects preserve their timing; refusals and unexpected exceptions have the existing rollback behavior, and uncertain commits do not authorize blind retries or duplicate external work.

**Verify:** Inject handler refusal, observer refusal/exception, connection loss and commit-acknowledgment loss. Check child-write rollback, correct failure journal or full rollback, no premature post-commit effect and exact-command reconciliation without a second handler/assistant invocation after a committed outcome.

### AC-6

A conforming host payload adapter durably publishes and returns exact authorized bytes without a filesystem dependency, using the corrected packet mapping and preserving explicit availability and integrity failures.

**Verify:** In a synthetic host fixture, locate by packet_hash and reconstruct canonical_bytes(exact_material); compare source_digest and byte length with Matter's content reference. Include unequal evidence_hash/payload digest, shared material, missing/changed/foreign/withheld packets, an interrupted put and exact raw response recovery. Prove the digest-only read route can resolve its scoped packet association and cannot treat identity hashes as payload hashes.

### AC-7

Versioned migrations and actual PostgreSQL restore verification recover the ledger together with its payload/artifact dependencies, including pending pressure and unresolved wakes, without fabricating completed or quiet work.

**Verify:** Exercise interrupted migrations, checksum/corruption refusals and a real dump/restore into a separate PostgreSQL target with synthetic host payload/artifact rows. Verify canonical histories, heads, watches, exact retries, pending pressure and unknown claims; missing payloads remain explicit. Row counts or schema checksums alone are insufficient.

### AC-8

The SDK compatibility and recovery contract preserves supported stored meanings and the SQLite reference, refuses unsupported versions and requires compatible SDK/image, ledger and payload recovery pins.

**Verify:** Run supported and deliberately unsupported version fixtures, including dev20-era historical-context behavior and MAT-074 compatibility vectors, on the backend matrix. Document one-way boundaries and verify a compatible restored recovery set rather than claiming that an older image can read newer state.

### AC-9

The receiving handoff names both permanent ports as StateCivics production prerequisites and assigns host payload implementation, coordination and storage recovery acceptance to KS-1158 without an interim production filesystem plan. Encryption remains KS-637/KS-1152 work; the production dispatcher and activation retain their separate StateCivics/owner scope.

**Verify:** Review the SDK guide and acceptance matrix against Decision 0003 and the pinned StateCivics request; identify executed Matter checks and still-required connected receiving evidence separately. Keep real rehearsal artifacts external and frozen wire/schema checks unchanged.

## Required test cases

- Exact retry after restart or lost commit acknowledgment versus changed command content under the same key.
- Absent identity and watch races between independent backend/worker connections, plus lens claims spanning different revisions and native matters.
- Snapshot consistency, current-head-gated historical proofs and present revocation on replay disclosure.
- Handler/observer rollback and post-commit timing under injected storage faults.
- Packet identity hash differs from payload digest; reconstructed exact bytes, raw response artifacts, withheld reads and corrupt mappings remain distinguishable.
- Restore of pending pressure, an unknown wake and all referenced payloads; missing bytes never become successful empty evidence.
- Supported and unsupported SDK/schema combinations with SQLite comparison and optional dependency installation.

## Risks

- PostgreSQL transaction isolation and locks are not interchangeable with SQLite's writer lock; absent reads and watch discovery require an explicit proof under real contention.
- A pool lease or caller-owned transaction can accidentally expose uncommitted success, retain locks or commit unrelated host work unless ownership is enforced.
- PayloadStore reads are digest-based while StateCivics packets are found by packet_hash; a missing scoped association or identity-hash substitution can break recovery or disclose foreign bytes.
- Execution receipts and raw responses may contain client-sensitive material; database custody does not remove host access, encryption and recovery obligations.
- A shared database does not make external assistant calls or host and Matter commits atomic; unknown wakes must retain their existing reconciliation controls.
- Production activation waits for permanent storage and separately recorded host acceptance; SDK conformance alone is insufficient and no temporary production mount is authorized.
