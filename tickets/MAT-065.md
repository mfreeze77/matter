## Purpose

Maintain only applicable, source-linked experimental fingerprints and assessments as rosters, rooms, microphones, questions, models and reference permissions change. Revocation invalidates affected future hints while historical receipts remain reproducible; no automatic enrollment or threshold relaxation follows.

## In scope

- Corpus/profile/model/question version compatibility
- Roster/chair/channel/coverage drift
- Reference/source revocation and correction dependencies
- Private pilot qualification/rollback receipts

## Scope boundaries

- Automatic production retraining, deployment or identity policy changes
- Deleting original evidence because an experimental matter resolved
- Treating expired qualification as valid through cache reuse

## Implementation

1. Define profile compatibility keys covering corpus/provenance map, source references, roster/role regime, extractor/model/question/threshold versions and supported population/time scope.
2. Detect bounded changes in feature availability and distributions by meeting/role/channel; record drift and propose requalification instead of silently widening applicability or relaxing confidence thresholds.
3. Apply source corrections and revoked reference samples through dependency invalidation; prevent them entering future profiles/packets and withdraw or regenerate pending private attention.
4. Preserve old assessment/package/configuration receipts and reference dispositions so historical results remain inspectable; separately record privacy/retention actions under the domain's approved policy.
5. Create a staged pilot qualification and rollback receipt with executed/unrun checks, quality/cost/coverage deltas and explicit operator scope for any future real inference; production remains untouched.

## Acceptance criteria

### AC-1

A revoked sample cannot support new or queued assessments while historical receipts retain the original evidence basis.

**Verify:** Revoke a shared reference after assessment selection and verify dependency invalidation, no fresh use and preserved historical manifests.

### AC-2

Expired, mismatched or failed qualification cannot be bypassed by a cached model result.

**Verify:** Replay cached answers across question/model/profile changes and inspect named unqualified outcomes.

### AC-3

Chair/channel/roster drift creates explicit regime/requalification state rather than automatic identity changes.

**Verify:** Run controlled profile shifts and compare production state digests and experimental eligibility.

### AC-4

The maintenance report separates readiness, inference execution and actual production scope.

**Verify:** Inspect a pilot receipt with no deployment and verify every future integration gate remains explicitly pending.
